01 · IP 怎麼來的

DHCP vs 固定 IP

不是二選一——兩者可以並存。

固定 IP（Static）

人員手動把 IP、遮罩、閘道、DNS 逐一寫進裝置，不會自動改變，也不依賴伺服器。

DHCP（自動發派）

主機開機後自動向 DHCP 伺服器索取 IP 與設定。RFC 2131 設計目標明文：「DHCP must coexist with statically configured hosts.」

很多人把 DHCP 直接等同於「每次拿到不一樣的 IP」——其實不然。它有三種模式。

RFC 2131 §1, §1.6
01 · DHCP 的三種分配模式

三種模式，不只是「動態」

Automatic

自動分配

配給 client 一個永久 IP。結果也是固定 IP，只是由 DHCP 統一發派。

Dynamic

動態分配

配給有限期的 IP（lease 租約），到期可回收再用。家用/企業最常見。

Manual

手動分配

IP 由網管指定，DHCP 只負責傳給主機。即「保留位址 / 綁 MAC」。

判斷原則：員工電腦用 Dynamic；印表機/伺服器要穩定，用 Manual 或純固定 IP。

RFC 2131 §2.2, §3.1
02 · 私有 IP 網段

192.168.x / 10.x 從哪來？

RFC 1918 保留了三個 IPv4 區塊供私有網路使用——不需申請、可重複使用，但不能直接在公開網路上路由。

10.0.0.0/810.0.0.0 – 10.255.255.25524-bit 區塊
172.16.0.0/12172.16.0.0 – 172.31.255.25520-bit 區塊
192.168.0.0/16192.168.0.0 – 192.168.255.25516-bit 區塊

「packets with private source or destination addresses should not be forwarded across such links.」
→ 所以家用裝置要上網，必須靠路由器做 NAT 把私有 IP 換成公開 IP。

RFC 1918 §3, §5
02 · 網段怎麼切

網段 = CIDR 前綴

斜線後面的數字代表「網路部分」有幾個 bit。

192.168.1.0 /24

192.168.1 | .0 – .255

前 24 bit 是網段，第四個數字是主機編號。
可用主機：.1 ~ .254（共 254 個，.0 是網路、.255 是廣播）。

「同網段」怎麼判斷

看的不是數字像不像，而是前綴是否相同：

192.168.1.10/24 ↔ 192.168.1.20/24 → 同網段 ✓

192.168.1.10/24 ↔ 192.168.2.10/24 → 不同網段 ✗

RFC 4632 §3.1
03 · Ping 走的協定

Ping = ICMP Echo

ping 用的不是 TCP、不是 UDP，而是 ICMP（RFC 792）。

Type 8 · Echo
來源主機送出「回聲請求」
→
Type 0 · Echo Reply
目的地原封不動回傳

「The data received in the echo message must be returned in the echo reply message.」
→ 有沒有收到回應、往返多久，就判斷連線通不通。

但 ICMP 封包要送達之前，還得先過 ARP 這一關 ⬇

RFC 792
03 · 為什麼同網段才通

關鍵：ARP 是「本地廣播」

要在乙太網路上送封包，得先知道對方的 MAC 位址——靠 ARP（RFC 826）以廣播詢問。而廣播過不了網段邊界。

✓ 同網段

ARP 廣播找得到對方 MAC → ICMP Echo 直接送達 → 對方回 Reply → ping 通。

✗ 不同網段

目的地不在本地廣播網域 → ARP 廣播到不了對方（路由器不轉送廣播）→ 封包送不出去 → ping 不通。

「It then causes this packet to be broadcast to all stations on the Ethernet cable.」
—— 廣播只在「同一條乙太網路 / 同一廣播網域」裡有效。

RFC 826
04 · 跨網段要路由器

不同網段 = 不同廣播網域

兩個網段要互通，必須有一台在第三層（L3）轉送的設備——路由器。

05 · 怎麼選

TCP vs UDP

特性TCPUDP
連線要（三向交握）不用
可靠性保證送達、不丟、有序不保證
速度 / 延遲較高（握手·確認·重傳）較低
表頭大小20 bytes 起固定 8 bytes
常見應用HTTP · SMTP · FTP · SSHDNS · DHCP · 視訊／語音 · 遊戲

判斷原則：「資料不能錯、不能少」用 TCP；「快比準確重要，或自己處理可靠性」用 UDP。

RFC 9293 · RFC 768
Takeaway · 核心邏輯鏈

兩條主軸，一句話各一行

連通層 L1 → L2

IP 在網路層定址 → 網段由前綴切分 → 同網段靠 ARP 廣播解析 MAC 直送 → ping 用 ICMP Echo 測試 → 跨網段廣播過不去，必須交給路由器轉送。

應用層 L3 → L4

IP 只「盡力送」、不保證送達 → TCP 用序號／確認／重傳補上可靠性與有序 → UDP 不加這些、換取低延遲。應用程式依需求挑選。

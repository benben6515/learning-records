心智地圖

在動手跑流程之前，先有一張地圖。一個你能在腦中握住的核心觀念。

你的任務，是把自己對這個專案的想法，從一個模糊的念頭，一路驅動到真正交付的變更。在任何一項技能之前，你需要的是整個系統的形狀——因為每一項技能，不過是同一條路線上的一個階段。

一個核心觀念

Matt Pocock 的技能不是一盒互不相干的指令。它們構成同一條幾乎所有工作都會走過的路徑：

grill-with-docs → to-spec → to-tickets → implement → code-review
想法  ⟶  交付  ·  全程由 domain-modeling 撰寫 CONTEXT.md + ADR

從左讀到右。你從一個想法開始，用訪談把它磨利（grill-with-docs），凍結成規格（to-spec），拆成可施工的票（to-tickets），逐張施作（implement），提交前審查（code-review）。規格驅動開發，就是中間這一段——grill-with-docs → to-spec → to-tickets——這也是我們最先要學的。

單一視窗紀律（context hygiene） 把 grill-with-docs → to-spec → to-tickets 留在同一個未中斷的上下文視窗裡完成。盤問、規格、票必須建立在同一份思考上——所以在票誕生之前，不要壓縮、也不要清空對話。之後每一張 implement 都從全新的視窗開始，只讀自己的那張票。若你在 to-tickets 之前就逼近智慧區（smart zone）（約 12 萬 token），就交接（/handoff）——別在衰退的推理上硬撐。

為什麼這對你很重要

你已經很會操作代理了。把這套工具用得跌跌撞撞的人，和用得交付順利的人，差別不在於知道每個指令做什麼，而在於知道自己此刻位於路線的哪一站，以及「同一個連續視窗、之後再分艙施工」這項紀律。把地圖和這條規則握住，其他都是你查得到的細節。

你的具體收穫 — 把這些說出口

  1. 依序說出主流程的五個階段。
  2. 指出哪一段算是「規格驅動」。
  3. 說出那條視窗紀律，以及你什麼時候才允許清空視窗。

如果三題都能不看著答案答出來，地圖就在你手裡了。本課程其餘部分，就是在填滿各個階段——從入口 grill-with-docs 開始。

## 全書核心公式

**Agent = LLM + 上下文 + 工具**　也就是　**大腦 + 眼睛 + 手腳**。

- **LLM**：決策核心（對應 RL 的 Policy）。
- **上下文**：決定 Agent 能看到什麼（對應 Observation Space）。
- **工具**：決定 Agent 能做什麼（對應 Action Space）。

模型固定時，擴展觀察空間與動作空間是最主要的能力槓桿；而**模型商品化後，競爭優勢轉向 Agent = Model + Harness 的 Harness 層**（上下文管理 + 工具介面 + 約束 + 驗證 + 糾正）。書中反覆強調一句話：**「好的設計原則本就應該穿越模型的迭代週期。」**

## 第一章：AI Agent 入門

**一句話總結**：現代 Agent 的本質是 LLM + 上下文 + 工具三者協同、由 ReAct 迴圈驅動，而生產級競爭力來自模型之外的 Harness 工程。

### 核心概念
- **Agent = LLM + 上下文 + 工具**（= 大腦 + 眼睛 + 手腳）。LLM 是決策核心，上下文決定能看到什麼，工具決定能做什麼。
- 對應 RL 三概念：LLM = Policy、上下文 = 觀察與歷史、工具 = 觀察／行動介面。
- **ReAct 迴圈**（思考→行動→觀察）：上下文 = 靜態字首（系統提示詞 + 工具定義）+ 動態軌跡，軌跡不斷追加以推進任務。
- **Agent = Model + Harness**；Harness = 上下文管理 + 工具介面 + 約束 + 驗證 + 糾正。
- 三原則：保持簡單、保持透明、設計好 ACI（防呆設計）。

### 關鍵取捨
- 通用工具利於組合與探索，專用工具用於約束高風險／強業務規則操作——通用並非永遠更好。
- **工作流**（確定性、安全、缺變通）vs **自主 Agent**（靈活、動態決策、高成本與複合錯誤風險）；應循「提示詞→工作流→自主 Agent」由簡到繁，實踐中常混合。
- 模型越自主，Harness 越關鍵：方向上認同 Sutton《苦澀的教訓》（模型終將吃掉 Harness），節奏上務實補位。

### 重要實驗
- **實驗 1-1：上下文的關鍵作用（消融實驗）**（★★）— 逐一移除五元件，證明工具定義、工具結果、思考過程、歷史訊息缺一不可，否則 Agent 失能、死循環或失憶。
- **實驗 1-2 / 1-3：Kimi K3 與 GPT-5.6 原生 Agent 能力**（★）— 展示「模型即 Agent」：RL 內化的是工具呼叫決策策略而非工具本身，長鏈呼叫穩定性與意圖澄清機制為亮點。

## 第二章：上下文工程

**一句話總結**：給模型看什麼、怎麼組織，往往比模型本身有多聰明更影響 Agent 的最終能力——上下文品質才是 Agent 能力的真正上限。

> 全書最關鍵的一章。

### 核心概念
- **上下文就是訊息列表**：`system` / `user` / `assistant` / `tool` 四種角色 + `tools` 欄位；每次 API 呼叫皆無狀態，須由框架重建「靜態字首 + 不斷增長的軌跡」。
- **KV Cache 三條鐵律**：(1) System Prompt 與工具定義一旦確定絕不改動（哪怕一個空格）；(2) 動態資訊永遠追加到對話末尾；(3) 一律使用標準 API 格式，勿自行拼接訊息。KV Cache 加速單次推理，Prompt Cache 跨請求複用前綴（讀取約十分之一成本）。
- **Prompt Engineering**：流程驅動（SOP）優於規則堆砌；業務規則須由產品經理細化到可執行（含正例反例）；工具描述精心設計使用邊界與示例。
- **Agent Skills（漸進式披露）**：少量目錄常駐、完整正文按需載入，避免系統提示詞膨脹稀釋注意力。
- **Agent 狀態列（Context Distillation）**：在上下文末尾以 `user` 訊息注入結構化元資訊，把「需要思考才能得到的結論」變成「可直接檢索的知識」——弱模型補回準確率，強模型省下效率。
- **Context Compression**：壓縮不只控制長度，更把原始記錄「換」成高密度結論；防範「上下文腐化（Context Rot）」（裝得下卻找不到）。

### 關鍵取捨
- **快取穩定 vs 動態狀態**：快取經濟性是「前置架構約束」而非事後最佳化——所有動態元素須放在快取邊界之後。
- **狀態列兩種更新法**：每輪替換（短後綴失效，避免陳舊累積）vs 持久追加（快取完全友好，但舊狀態佔 token）。
- **隔離優於壓縮**：子 Agent 上下文隔離讓海量中間過程根本不進主上下文，是比事後有損壓縮更釜底抽薪的做法。

### 重要實驗
- **實驗 2-4：提示工程消融**（★★）— 規則打亂成無序集合致成功率下降 30%+，移除工具描述致呼叫錯誤率 +45%。
- **實驗 2-9：上下文壓縮策略對比**（★★★）— 上下文感知壓縮（3% 壓縮率）token 減少 75% 以上，遠勝非任務感知壓縮；適應性視窗化則在初期保留完整資訊、近閾值才批次壓縮。

## 第三章：使用者記憶和知識庫

**一句話總結**：將使用者記憶與 RAG 技術統一在檢索增強框架下，建構從「記住事實」到「主動服務」的持久化體系，並以「雙層架構」（結構化概覽常駐 ＋ 按需檢索細節）為最高階能力的落地路徑。

### 核心概念
- **記憶評估三層次**：基礎回憶（精確存取）→ 多會話檢索（跨時間／物件關聯）→ 主動服務（發現隱藏關聯、預見性幫助）。
- **四種漸進式儲存格式**：Simple Notes（原子事實、O(1)）→ Enhanced Notes（完整段落）→ JSON Cards（類別巢狀）→ Advanced JSON Cards（含 backstory／person／relationship，解決實體消歧）。
- **RAG 完整技術棧**：文件分塊 → 稠密嵌入（語義、餘弦相似度）＋ 稀疏嵌入（BM25 關鍵詞精確匹配）→ 混合檢索（並行檢索 → RRF 融合 → Cross-Encoder 重排序精排）。
- **結構化索引**：RAPTOR（樹狀層次摘要）、GraphRAG（實體關係圖譜，擅長多跳推理與實體消歧）、OpenViking（L0/L1/L2 檔案系統按需載入）。
- **Agentic RAG**：將知識檢索封裝為工具，由 Agent 以 ReAct 模式自主決定何時檢索、檢索什麼、是否迭代。
- **Contextual Retrieval（上下文感知檢索）**：索引期為文字塊補 LLM 生成的上下文字首，修補分塊固有的語義丟失。

### 關鍵取捨
- 儲存格式：關鍵少量資料用 Advanced JSON Cards 保可檢索性，大量事實用 Simple Notes 降成本，多數系統走混合。
- **Mem0 v2→v3**：衝突處理從寫入期（ADD／UPDATE／DELETE，可能不可逆遺失歷史）移至檢索期（僅追加 ＋ 時間排序混合檢索），減少 LLM 呼叫且避免遺失。
- **雙層記憶架構**：Advanced JSON Cards 常駐上下文提供「概覽」＋ Contextual Retrieval 按需取「細節」，兩者疊加才支撐起「主動服務」層級。
- 知識更新雙軌：增量更新（Proposer-Reviewer 異源互審 PR）及時吸收證據；定期整理回到原始資料去重、限定情境，避免摘要代代誤傳。

### 重要實驗
- **實驗 3-7：RAPTOR 與 GraphRAG**（★★★）— 以 CPU 手冊為語料，對比樹狀「跨層穿梭」與圖譜「關係漫遊」兩種知識表達哲學，證明二者解決不同查詢類型、宜組合使用。
- **實驗 3-11：Contextual Retrieval 增強使用者記憶**（★★★）— 結合 Advanced JSON Cards（概覽）與 Contextual RAG（細節）為雙層架構，在跨會話事實衝突與護照過期預警場景達到「主動服務」層級。

## 第四章：工具

**一句話總結**：工具設計的質量決定 Agent 的能力上限，而非同步架構決定 Agent 能否在真實世界中可靠執行——本章圍繞「工具選擇」與「非同步事件」兩大挑戰，給出五類工具的設計原則與事件驅動架構。

### 核心概念
- **五類工具**按呼叫方向／作用物件劃分：感知（取資訊）、執行（改變世界）、協作（驅動其他 Agent／人）、使用者溝通（傳遞資訊）、事件觸發（Agent 註冊、外部喚醒）。
- **通用設計原則**：粒度權衡（功能相似才整合）、通用優於專用（code_interpreter 勝過多個計算器）、描述要說明「何時用」與邊界（反例比能力更重要）、附帶 1-5 個真實呼叫示例（準確率可從 ~72% 升至 90%）。
- **參數保真性是底線**：嚴禁靜默輸入轉換或引數注入——模型感知的世界與工具操作的世界不能有系統性偏差（如 Cursor 彎引號被偷偷轉直引號導致無法匹配）。
- **MCP（Model Context Protocol）** 是 Anthropic 提出的工具互操作標準，採 client-server 架構，分離「工具／資源／提示」三類原語，實現「一次開發、處處可用」。
- **執行工具安全三層**：輸入驗證 → 權限控制 → Proposer-Reviewer（事前審批用不同家族能力相近的模型互審、事後驗證用模態切換）＋ Sidecar（旁路輕量 LLM 僅看結構化欄位做門控，防提示注入）。

### 關鍵取捨
- **工具表達形態**：專用程式碼工具（結構化、可測試但佔 token）vs Skill + 通用執行器（自然語言、輕量但依賴模型能力），依參數複雜度／變更頻率／模型能力三維決定。
- **工具過多的兩條路**：MCP 主動發現（嵌入索引＋語義匹配＋動態注入，工程繁瑣）vs Skills 漸進式披露（只暴露薄目錄，像查維基百科按需讀取，更省心）。
- **非同步矛盾**：LLM 訓練假設同步（tool call 後必接 tool result），部署卻要非同步——目前用佔位符、啟動／完成解耦的工具介面、狀態列標記等提示工程權宜，根本解法待下一代模型在非同步環境中做 RL。
- **事件處理三策略**：取消式（緊急，提前製造安全點）、佇列式（常規，批次處理）、並行式（獨立輕查詢，另起迴圈）。

### 重要實驗
- **實驗 4-4：事件驅動郵件處理 Agent**（★★★）— 監聽收件箱，新郵件觸發分類／摘要／起草回覆，展示「事件到達→Agent 處理→結果輸出」的基本閉環。
- **實驗 4-5：帶並行執行和打斷能力的非同步 Agent**（★★★）— 進入非同步深水區：並行工具執行、使用者「停止」立即取消、多任務狀態查詢與動態取消決策。
- **實驗 4-6：主動工具發現**（★★★）— 用 Qwen3-4B 配 120+ MCP 工具，對照全量注入 vs `discover_tools` 元工具按需載入，驗證小模型在大工具庫下的可用性。

## 第五章：Coding Agent 與程式碼生成

**一句話總結**：Coding Agent + 檔案系統是開放任務型通用 Agent 的核心架構基礎，而程式碼生成是一種能在執行時動態創造新工具與能力的「元能力」。

### 核心概念
- **核心判斷**：以開放任務為目標的通用 Agent，其核心 = Coding Agent + 檔案系統；從 Manus 到 OpenClaw 的成功實踐都遵循此正規化。
- Coding Agent 僅需七個核心工具：Code Interpreter、Bash、Read、Write、Edit、Glob、Grep。
- **檔案系統作為 Agent 中樞**：記憶存於 `MEMORY.md`（選 Markdown 而非向量資料庫——可讀、可改、可 Git 版控、保留時間順序），產物與經驗也落地為檔案。
- 程式碼的雙重價值：**思考**上形式化嚴謹無歧義（`age > 18 and is_verified`），**表達**上可執行即自洽證明、提供客觀對錯標準。
- **Harness 工程**：Coding Agent 是可驗證性最高的場景，軟體工程數十年基礎設施（測試套件、Linter、型別系統、Git）天然構成強大 Harness——成熟度高非因模型強，而是因基礎設施紮實。

### 關鍵取捨
- **適用邊界**：「以 Coding 為核心架構」主要適用開放任務型 Agent；垂直領域 Agent（客服、語音助手）中程式碼只是工具，但 coding 能力是所有 Agent 的共同底線。
- 安全防線圍繞「致命三要素」（訪問私有資料、暴露於不受信任內容、具備外部通訊）+ 持久記憶作為攻擊放大器；防禦靠沙盒隔離、網路出口白名單、語義解析（非關鍵字黑名單）、推測性執行讓安全檢查隱形。
- 當 AI 寫的程式碼本身不可信時，**把信任邊界下移到資料層**——約束不能待在被生成的程式碼裡，而要在人類審查過的地基裡強制執行（權限內嵌資料物件）。
- 故障恢復：錯誤處理邊界是整個恢復迴圈而非單次請求；每條恢復路徑都要有熔斷上限（如壓縮連續失敗 3 次即放棄，閾值來自產線資料）。

### 重要實驗
- **實驗 5-3：小模型透過程式碼化知識提升執行規則的準確性**（★★）— 驗證「系統提示詞自然語言規則 + 引數作 checklist + 服務端真值校驗」三重保障，使小模型在 τ-bench 複雜政策執行上顯著提升，並揭示模型與 Harness 此消彼長的關係。
- **實驗 5-13：開發一個能創造 Agent 的 Agent**（★★★）— 展示 Agent 自舉（bootstrap）的終極形態：透過「自我複製並適應性修改」基於範例生成新 Agent，而非從零寫起，證明程式碼生成可實現智慧的自我繁殖。

## 第六章：Agent 的評估

**一句話總結**：完善的評估體系首要價值不是給當前系統打分，而是讓團隊能快速可靠地跟上模型演進——擁有評估集者數小時內即可做出切換決策，憑直覺者只能被動等待。

> 書中反覆強調：「沒有評估，就沒有進步。」

### 核心概念
- 評估三層架構：評估環境（在哪測）→ 評估方法（怎麼判）→ 評估驅動決策（測了幹什麼），形成「觀察→假設→實驗→驗證」的完整閉環。
- 評估物件是「模型＋Harness 組合體」而非單獨模型；模型替換實驗（固定 Harness 換模型）區分瓶頸在模型還是 Harness，消融實驗則定位 Harness 內哪個元件重要。
- 兩種環境正規化：工具呼叫型（Verifiers 的 SingleTurn / Tool / StatefulTool / Sandbox 分層）與人機互動型（τ-bench / τ²-bench 的使用者模擬＋漸進式資訊透露）；規模化後演化為模擬環境，通往第七章後訓練。
- 指標切勿混用：`Pass@k = 1-(1-p)^k` 衡量能力上限、`Pass^k = p^k` 衡量穩定性，`Best@k` 看質量天花板。
- LLM-as-a-Judge 配 Rubric 四準則（專家指導、全面覆蓋、權重分級含一票否決 Veto、自包含評估），並防範長度偏差與獎勵作弊（Reward Hacking）。

### 關鍵取捨
- 資料集設計五大張力：明確性 vs 開放性、真實性 vs 可控性、多樣性 vs 系統性、成本 vs 覆蓋、資料洩漏防範（動態參數生成、canary GUID、時間新鮮度）。
- 同源模型問題觸發古德哈特定律（Goodhart's Law），須用多源異構評判——不同家族評委的偏見往往正交。
- 多項上下文優化（KV Cache＋壓縮歷史）的節省比例不能直接相加，必須在完整任務中一起實測。
- 分差小於統計噪聲頻寬時不做切換；應優先用配對分析（McNemar）而非兩獨立成功率相減，並校正多重比較。

### 重要實驗
- **實驗 6-12：AndroidWorld 的評估和改進**（★★★）— 完整示範 H1（加導覽提示無效）→ H5（換 UIAutomator 解決「看不見」但 token 暴增）→ H5C（精簡元素樹 token 減半），示範「每輪只改一個變因」的迭代閉環。
- **實驗 6-4：Advanced JSON Cards vs RAG 對比**（★★）— 混合系統並未自然勝出，打破「結構化＋檢索必有協同」的直覺，跨會話關聯題 RAG 成功率僅 15%。
- **實驗 6-9：端到端成本分析**（★）— 八輪任務中快取＋壓縮合用僅省 30%（非 28%＋17% 相加），證明優化疊加須實測。

## 第七章：模型後訓練

**一句話總結**：模型能力分「預訓練→SFT→RL」三階段煉成——SFT 固化格式與協定（記憶），RL 學會可遷移策略（泛化），而真正決定成敗的是資料與環境，不是演算法。

### 核心概念
- **三階段流水線**：預訓練（預測下一個詞，積累知識）→ SFT（換資料的 NTP，loss masking 只算在回答上，固化「輸入→輸出」對映與協定）→ RL（最大化期望獎勵，探索可遷移策略）。
- **SFT 記憶、RL 泛化**：源於最佳化目標不同——SFT 最大化標註答案機率（mass-covering、離線、天花板是示範者水平）；RL 最大化期望獎勵（mode-seeking 反向 KL、線上、天花板是任務本身，能發現示範外的更優策略）。
- **必須先 SFT 後 RL**：SFT 先把「形」（可解析的輸出格式）立穩，獎勵訊號才計算得起；RL 再追求「神」。強基模可跳過 SFT（DeepSeek-R1-Zero），但仍需冷啟動 SFT 補回可讀性。
- **資料與環境比演算法更重要**：優先序為先驗（基模）> 環境（保真度）> 演算法；SFT 資料品質到位時往往不需 RL。
- **獎勵訊號譜系**：二元獎勵（可驗證任務）→ 過程獎勵（PRM，密集但約束探索）→ 結果獎勵（ORM，自由但稀疏）；主流演算法 PPO（價值網路+裁剪）、GRPO（組內相對比較、免價值網路）、DPO（離線偏好）。
- **樣本效率兩條路**：On-Policy Distillation（在軌+稠密訊號，達同等效能只需純 RL 約 1/10 步數）；OPSD（同模型分飾看答案的教師與只見題的學生，靠特權資訊產生稠密監督）。

### 關鍵取捨
- **「獎勵結果、約束過程」（RLVP）**：純結果獎勵在「全敗組/全勝組」組內方差為零、學不到東西；用可驗證的確定性規則引擎懲罰壞動作（永遠可達）+ 部分獎勵獎勵可達進展（reachability-gated）補回方差。
- **懲罰只打可驗證的「動作」、絕不懲罰「沒進展」**——否則落入「不作為陷阱」，Agent 學會什麼都不幹；結果獎勵必須是主驅動力。
- **模型模擬環境（ZeroSearch / DreamGym）**：造不出真實環境時可行，但模擬器的系統性偏差就是訓練的天花板，需混合真實互動校準。
- **SFT 不適合注入事實知識**——那要靠繼續預訓練或 RAG；SFT 只固化「如何使用知識」的協定性知識。

### 重要實驗
- **實驗 7-11：GeneralPoints——單輪 RL 的記憶與泛化對照**（★★）— 在規則 OOD 上 RL +3.5%、SFT 反降 8.1%，系統量化「SFT 記憶、RL 泛化」並證明未經 SFT 直接 RL 在小基模上完全失敗。
- **實驗 7-13：SimpleVLA-RL——結果獎勵**（★★★）— 僅用二元獎勵的 GRPO 在機器人操作上讓模型自主湧現「推切」新動作（從未見於人類演示），直接證明 RL 能超越示範、發現更優策略。
- **實驗 7-16：RLVP——獎勵結果、懲罰路徑**（★★★）— TerminalBench 違規次數降約 6 倍而成功率持平；miniF2F 達 0.9 成功率所需迭代數從 7.0 降到 4.4，證明「守規幾乎免費、進展獎勵在可達時加速收斂」。

## 第八章：Agent 的持續進化

**一句話總結**：現今模型無法可靠地自行持續學習，必須在模型外圍建立一套「記錄證據→評價軌跡→產生候選→驗證發布→整理回滾」的可驗證閉環，將執行經驗轉化為下一版本能力。

### 核心概念
- **保存經歷 ≠ 從經歷中學習**：把軌跡塞進向量庫只會「記得」，唯有主動完成評價、對照、歸納、驗證才算學會「在什麼條件下應該如何行動」。
- **學習訊號三層驗證**：底層環境結果（測試/訂單狀態）→ 中層過程規則（權限、流程）→ 上層 LLM Rubric（品質）。越往下越該用程式碼與環境真值，難以形式化者才交給 LLM，且必須輸出多面向結論加證據，而非單一純量總分。
- **四種更新載體依「能力可否由該載體表達」選擇**：知識文件（事實/經驗）、Prompt+Skill（可語言化規則）、程式+Harness（確定性流程/強約束）、模型參數（高維度感知/隱式策略）——選擇依據是表示性質而非穩定性。
- **雙循環結構**：線上循環只記錄不可變證據、不直接改寫正式 Agent；離線進化循環彙整軌跡、產生候選、通過門檻後分階段發布。
- **Voyager 三機制**：自動課程（下一步學什麼）+ 技能庫（持久化）+ 環境驗證（避免累積錯誤），缺一即退化。

### 關鍵取捨
- **最小 diff 優先於重寫**：候選修改應附來源、作用範圍與影響預測，反覆重寫整份 Prompt 會讓重要細節與相互制約的條件逐漸蒸發。
- **Harness 更新能力 ≠ Harness 受益能力**：一條正確的 Skill 若未被弱模型載入或遵循，端到端分數會誤判為「沒進化」；應固定候選換任務模型、或固定任務模型換更新器，雙向歸因。
- **安全信任根不可自我修改**：Agent 可改 Prompt/Skill/工具/參數，但驗證器、發布門檻、稽核日誌、穩定備份必須在可修改範圍之外，否則退化會被偽裝成進步。
- **離線整合（睡眠學習）取代即時寫入**：一次偶發成功或提示注入不該立即改寫長期能力；蒐集與整理分開，可用更大批次、更便宜模型，並週期合併重複、淘汰過期知識防上下文腐化。

### 重要實驗
- **實驗 8-4：從瀏覽器軌跡產生可驗證工作流程**（★★★）— 證明「動作前/動作後/儲存前」三層獨立驗證可避免「按鈕都點過但任務未完成」的假成功，頁面變化時自動失效退回重學。
- **實驗 8-5：由失敗軌跡觸發 Agent 自我修改**（★★★）— 跨軌跡支持門檻觸發後，Coding Agent 只能寫入隔離候選目錄並提交影響預測，通過失敗重播+舊任務迴歸才得 `release_to_canary`，將自我修改轉為可稽核的軟體發布流程。
- **實驗 8-7：評估 Agent 是否持續進化**（★★★）— 區分 static / append_only / evolving 三種長期行為，涵蓋遷移、規則變化、能力保留四階段，揭示「會保存回饋」不等於「能更新並保留能力」。

## 第九章：多模態與即時互動

**一句話總結**：當 Agent 從文字世界走向語音、GUI、機器人等物理互動場景，「即時性 + 多模態」兩道坎共同把架構從序列流水線推向端到端模型，並以「快慢解耦」作為三場景共通的解題方向。

### 核心概念
- **三場景共通主線**：語音、Computer Use、機器人都面臨持續流動的輸入與嚴格時間預算，卡點高度相似——都要同時處理多種模態，都對延遲極度敏感（語音停頓 >2 秒讓人焦躁，機器人毫秒級抖動可能碰撞）。
- **語音三範式**：級聯（VAD→ASR→LLM→TTS，模組化但延遲累積）、端到端 Omni（單模型保留副語言資訊但仍輪次）、全雙工（Moshi、GPT-Live，邊聽邊說，把「誰該說話」變成持續決策）。
- **思考架構三方案**：快思考應付/慢思考修正、快慢解耦委派（後臺推理模型當「軍師」）、端到端統一（Step-Audio R1 的 MGRD + MPS 雙腦實現「邊想邊說」）。
- **Computer Use 迴圈**：感知～思考～行動；視覺定位三路線——Set-of-Mark（選擇題）、DOM/Accessibility Tree 結構化索引、純座標預測（SeeClick、Claude，依賴訓練解析度匹配）。
- **機器人雙層架構**：長程規劃（VLM/Gemini Robotics-ER，管「做什麼」）+ VLA 控制（RT-2、OpenVLA、π₀，管「怎麼做」），靠 Action Chunking 攤薄推理延遲。

### 關鍵取捨
- **序列流水線 vs 端到端**：模組化易除錯替換，但邊界累積延遲且副語言資訊在離散介面遺失；端到端省交接、保情緒，但訓練與除錯成本高——優勢在延遲與非文字資訊，非整體準確率。
- **動作分塊的代價**：用反應性換平滑性——塊越長延遲攤得越薄、運動越連貫，但對突發變化（物體被挪走）越遲鈍。
- **Computer Use 瓶頸轉移**：OSWorld 準確率已接近人類，但操作步驟多、步驟耗時隨任務增長，「效率」成為真正未解難題；可用繞道是快慢解耦——語音（快）+ 操作（慢）並行，僅靠純文字契約溝通，延遲降約 15 倍且成功率不降。
- **機器人主矛盾轉向**：即時性被雙層解耦 + 動作分塊部分緩解後，主要矛盾轉到 VLA 控制層的「訓練與泛化」（跨任務、跨具身遷移）；對視覺回饋類家庭任務，硬體已非瓶頸（觸覺、靈巧手仍是短板）。
- **Sim2Real 兩個工程環節**：隨機化範圍須實測標定（太窄覆蓋不足、太寬學成次優策略）；視覺對齊須校準攝影機位姿 + greenscreen 背景替換。

### 重要實驗
- **實驗 9-3：MiniCPM-o 端到端 vs 自級聯**（★★）— 同模型兩路徑總分相同（3/4）但失敗位置互補，證明端到端優勢在副語言資訊（語速），自級聯在語義任務可修正感知錯誤。
- **實驗 9-7：XLeRobot 遙操作整理桌面**（★）— 千美元級機械臂配人類遙操作即可完成多步家庭任務，反證「硬體是瓶頸」，差距在感知、規劃、閉環控制與失敗恢復。
- **實驗 9-9：Gemini Robotics-ER 1.5 自主控制真機**（★★）— 用 Agent 取代人類遙操作執行同一任務，直接暴露感知、時機與失敗恢復的演算法鴻溝。

## 第十章：多 Agent 協作

**一句話總結**：多 Agent 協作的價值不在「讓模型多想幾遍」，而在於引入單個 Agent 生成時無法取得的新資訊（執行回饋、視覺驗證、工具確認），並透過設計資訊流動與控制權歸屬，讓群體湧現出超越個體的集體智慧。

### 核心概念
- **分類框架（2 維度）**：維度一「上下文是否共享」（共享=執行緒/隱式協調、不共享=程序/顯式協調）；維度二「協作拓撲」——對等（Peer）、管理者（Orchestrator）、去中心化（Decentralized）。
- **通訊機制三種**：工具呼叫引數、共享檔案系統（=共享記憶體）、訊息匯流排（=訊息傳遞），對應 IPC 兩大正規化。
- **虛擬檔案系統四區**：Scratchpad（私有）、Shared Workspace（共享+使用者可見）、外部掛載資源（唯讀為主）、系統內建資源（Skills，唯讀）。
- **Loop 工程**：瓶頸在驗證器而非模型——「模型可提出完成，但不能批准自己的完成」。
- **A2A 協定**（跨組織）：Agent Card（能力發現）+ 任務生命週期狀態機 + 不透明協作。

### 關鍵取捨
- **多 Agent 唯一正當性**：協作必須引入新資訊；同模型自我審查無效甚至有害（Huang, ICLR 2024），辯論在等計算量下不優於單 Agent（Tran, 2026）。
- **管理者模式瓶頸**：弱規劃者是系統上限（Plan-and-Act），最強模型應配給 Manager 而非平均分配。
- **成本紅線**：多 Agent 研究系統 token 消耗約為單 Agent 的 15 倍，收益須覆蓋數倍開銷才划算。
- **並行衝突**：單檔用樂觀鎖，多 Coding Agent 用 Git worktree 隔離（「隔離優於壓縮」），錯誤級聯放大須靠獨立交叉驗證打斷。

### 重要實驗
- **實驗 10-3：邊打電話邊用電腦的 Agent**（★★★）— Pine AI 場景，Phone Agent（ASR/TTS）與 Computer Agent（瀏覽器操作）非同步並行，示範異構 Agent 跨模態即時協作。
- **實驗 10-2：書籍翻譯 Agent**（★★）— Manager + Glossary/Translation/Proofreading 四 Agent，以責任分離控制上下文膨脹、保證全書術語一致。
- **實驗 10-5：史丹福 AI 小鎮**（★）— 25 個生成式 Agent 在記憶流/反思機制下，自發湧現情人節派對與市長選舉，示範去中心化的湧現式協調。

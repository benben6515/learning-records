Lesson 02 · Sci-Fi Terminal Panes

tmux Panes From Scratch

~15 min Layer 2 First config

Four tabs was a teaser. Movies show everything at once, in a grid. The tool that turns one terminal into that grid is tmux — already installed on your machine (3.7b) and completely unconfigured, which makes you lucky: you'll learn it clean, with no inherited habits.

The hierarchy: server → session → window → pane

tmux runs as a background server. You attach clients to it. Inside the server lives a session (a named workspace, e.g. bridge); a session contains windows (full-screen tabs); each window is split into panes — your sci-fi panels. The magic property: sessions survive terminal closure. Close Ghostty, reopen, re-attach — your bridge console is still running.

The prefix key tmux commands are two keystrokes: Ctrl-b (hold both, release) then a key. Ctrl-b is the "now I'm talking to tmux, not to the program" signal. It feels odd for a day, then becomes muscle memory.

Build the grid

$ tmux new -s bridge        # start a session named "bridge"

Now split — remember: prefix first, then the key:

  • Ctrl-b % — split left/right (vertical divider)
  • Ctrl-b " — split top/bottom (horizontal divider)
  • Ctrl-b ←→↑↓ — move between panes
  • Ctrl-b z — zoom one pane full-screen (toggle — brilliant for focusing)
  • Ctrl-b x — kill the current pane (asks y/n)

Split three or four times, launch one TUI per pane (btop, fastfetch, cmatrix, cbonsai -L 30) — this is the bridge console, and it took no configuration at all. Ride it with Ctrl-b d (detach), then come back:

$ tmux attach -t bridge      # your console is still alive

Your first config — three lines, zero scripts

tmux reads ~/.config/tmux/tmux.conf. Create the file with these three lines:

# ~/.config/tmux/tmux.conf
set -g mouse on                # click panes, drag dividers, scroll
set -g status-position top     # status bar up top, like a HUD
set -g default-terminal "tmux-256color"

Then reload without restarting: Ctrl-b :, type source-file ~/.config/tmux/tmux.conf, press Enter. (set -g means "global setting"; tmux-256color tells programs inside tmux that colors are safe to use.)

Config ≠ script A shell script is a program — logic you write. A config file is a list of settings a tool reads. Your mission bans scripts, embraces config: tmux.conf is declarative — every line is "set option X to Y". That's why the movie look needs no programming.

Why is the default bar ugly?

That green bottom bar is tmux's 1990s default. It's fully themeable — colors, content, modules — but by hand it's tedious. Next lesson we install the Catppuccin theme via a plugin manager, and the bar becomes a pastel HUD in one shot. That's the pattern to remember: themes are config consumed from packages, not code you write.

Do it now — build it twice

Building it from memory (not copy-paste) is what makes it stick. Round one with the lesson open; round two from memory:

  • Create session "bridge", split into 4 panes, one TUI per pane.
  • Zoom a pane with Ctrl-b z, then toggle back.
  • Detach with Ctrl-b d, close the Ghostty tab, re-attach with tmux attach -t bridge.
  • Write the 3-line tmux.conf and reload it live.
  • Kill everything, rebuild the whole grid from memory.

# Diagnosing bugs — the tight loop

The learner can state the refusal rule (no hypothesis before one runnable command that already goes red on the exact reported symptom) and explain why the tight loop is the skill — bisection and hypothesis-testing are mechanical once the signal exists. This matters because it is the hard-bug version of the feedback loop that keeps the agent from theorising blind.

**Evidence:** correctly required a red-capable loop before any hypothesis; chose a higher reproduction rate (loop, parallelise, stress) over a clean repro for flakes; asserted the exact reported symptom rather than a nearby failure; and handed a no-good-seam post-mortem to `improve-codebase-architecture`.

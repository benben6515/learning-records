# ADRs — the three-criteria gate (AND, not OR)

ADRs hold **decisions** (where `CONTEXT.md` holds *terms*), but only the rare decision a future explorer genuinely needs explained. The whole skill is **restraint** — most decisions you think deserve an ADR don't. The gate is an **AND gate, not OR**: offer an ADR only when **all three** hold — **(1) hard to reverse** (changing your mind later costs) **AND (2) surprising without context** (a future reader asks "why?") **AND (3) real trade-off** (genuine alternatives existed). Miss *any one* → skip. Easy to reverse → just reverse it, skip. Not surprising → nobody will wonder, skip. No real alternative → "we did the obvious thing," skip. This is the antidote to ADR-sprawl: folders of records nobody reads because they documented the obvious and the reversible.

**Format is deliberately tiny:** title + 1–3 sentences (what's the context, what did we decide, why). Lives in `docs/adr/`, sequentially numbered `0001-slug.md`, created lazily. Optional sections (`Status` frontmatter `proposed | accepted | deprecated | superseded by ADR-NNNN`, `Considered Options`, `Consequences`) only when they add genuine value. The canonical example: the `permissionBits` bitmask ADR — exists so the next person doesn't "refactor" the bitmask into roles and quietly break the menu filter.

**Terms vs decisions — the clean split (closes Lesson 5):** "What do we *call* this?" → `CONTEXT.md` (a term). "Why did we *choose* this?" → an ADR *(if it clears the gate)*. "We call it `permissionBits`" = term; "we made it a *bitmask*" = decision. Same concept, two homes.

**Evidence:** free-recall — stated the AND-gate (all three, miss one → skip); on the four-scenario drill, judged all four correctly: bitmask → ADR (all three); new/old coexistence → ADR + keep both old and new; eslint-config-standard → skip; hash-mode router → ADR. Notably reasoned that the old ADR must be retained (not deleted) during/after the migration.

**Misconception sharpened (not wrong, made precise):** on the eslint case, named "not surprising" as the failing criterion — defensible, but the reference's "what does NOT qualify" list **explicitly names lint config as the example of *easily reversible***. The cleaner hit is **criterion 1 (hard to reverse)**; "not surprising" is a secondary failure. Both reach the right call (skip); the precision matters when justifying a skip to a teammate.

**Nuance internalised on #2 (the genuinely hard call):** the new/old-coexistence ADR must document the **migration-strategy decision** (why incremental, why both coexist during transition) — NOT the ephemeral fact "we haven't finished." Documenting unfinished work is exactly the ADR-sprawl the gate prevents; documenting the *deliberate incremental-vs-big-bang trade-off* is what clears criteria 2 (surprising) + 3 (real trade-off). And ADRs are **append-only history**: the old approach's ADR is never deleted — once fully retired it gets `Status: superseded by ADR-NNNN`.

**Implications:** Lesson 7 is `to-spec` — the spec anatomy and the test-seam rule. With the two artefacts a spec is built on (glossary + ADRs) now in hand, the next lesson writes the spec itself — and the one rule about test seams most people get backwards ("fewest seams; ideal = 1").

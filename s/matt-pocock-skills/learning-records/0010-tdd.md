# TDD — red-green, one vertical slice

The learner can recite the red-green loop (one failing test, just enough code, refactor only while green) and explain why batching tests up front fails: batched tests check imagined behaviour and go numb to real changes. This matters because it is the feedback loop that gives the agent eyes inside every `implement` session.

**Evidence:** correctly ordered the loop (test → code → refactor, never refactor while red); rejected batched tests because they test imagined behaviour; identified recomputed expected values as the tautological-test trap; placed `tdd` as the engine inside `/implement`; and named `/codebase-design` as the neighbour that places the seam before any test is written.

**Implications:** ready for Lesson 11 — `diagnosing-bugs`, the hard-bug version of the same feedback loop.

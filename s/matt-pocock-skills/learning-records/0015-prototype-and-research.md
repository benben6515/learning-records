# Prototype & research — two standalone exploration tools

The learner can state each tool's contract: prototype is throwaway from day one (one design question, no tests/abstractions/persistence; hardening = stopped prototyping), and research is delegated legwork over primary sources that leaves a cited Markdown file behind. This matters because both answer a question fast and feed the result back into the main flow.

**Evidence:** correctly identified hardening as the stop-prototyping line; routed a misbehaving built feature to `diagnosing-bugs`; placed the spent prototype on a throwaway branch (unmerged, pointer on the issue); required primary sources with citations; matched the state-model question to the single-HTML- pushing-awkward-cases shape; described research's defining move as a background agent; and fed research output into `grill-with-docs` rather than straight to build.

**Implications:** ready for Lesson 16 — setup & triage, the issue-pipeline on-ramp.

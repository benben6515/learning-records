詞彙表

Matt Pocock 技能集的領域語言。每一課都在用這些術語。

技能自己的 CONTEXT.md 是權威來源。精確使用這些術語；別漂移到近似同義詞。

術語定義
議題追蹤器（Issue tracker）存放 repo issue 的工具——GitHub Issues、Linear、本地 .scratch/ markdown 慣例之類。to-tickets、to-spec、triage、wayfinder 等技能從它讀、也寫回它。避免：backlog manager、backlog backend、issue host。
Issue（議題）議題追蹤器裡單一被追蹤的工作單位——bug、任務、規格、或 to-tickets 產出的切片。避免 “ticket”，除非引述外部系統對它的稱呼，或指決策票（Decision ticket）。
決策票（Decision ticket）wayfinder 的單位——wayfinder:map 底下的一個子 Issue，持有一個問題，其解答是一個決策，不是待施工的建置切片。正是決策這個限定詞讓它有別於實作 issue。
分級角色（Triage role）分級時貼在 Issue 上的標準狀態機標籤（如 needs-triage、ready-for-agent）。每個角色經由 docs/agents/triage-labels.md 對應到議題追蹤器裡的真實標籤字串。
智慧區（Smart zone）模型仍能敏銳推理的上下文視窗大小（最先進模型約 15 萬 token）。session 在 to-tickets 前逼近它，應該在最近的階段邊界（phase boundary）執行 /compact，別硬撐退化中的推理。aihero.dev 字典。
接縫（Seam）（Feathers 的術語）不改那里的程式碼就能改變行為的地方。功能接受測試的穩定介面。接縫放得好，測試就有耐久的瞄準點，底下的程式碼可以自由變動。在任何程式碼寫下之前選定（to-spec 期間）。
深模組（Deep module）在小而穩定的介面後面藏住大量行為的模組。深度以槓桿衡量——呼叫者（或測試）每學一單位介面，能驅動多少東西。相反：淺（介面幾乎跟實作一樣複雜）。
深度（Depth）介面的屬性，不是實作的。深模組內部可以由許多小而可替換、永不浮現給呼叫者的部件組成。
阻塞邊（Blocking edges）票與票之間的依賴連結。每張票宣告哪些票阻塞它。在真追蹤器上這些是原生阻塞連結；本地則是每票一檔裡的文字。未被阻塞、未被認領的票集合就是前緣。
前緣（Frontier）開放、未被阻塞、未被認領的票——wayfinder 裡已知世界的邊界，或 to-tickets 裡可拿的工作。追蹤器的原生阻塞渲染會把它畫出來。
曳光彈（Tracer bullet）貫穿所有整合層的薄垂直切片（schema、API、UI、測試），自己就能 demo。第一圈 TDD 先證明一條路端到端走得通，再向外建。相反：水平切片（單一層，全部到齊前什麼都不能動）。
共用語言（Ubiquitous language）（DDD，Evans）開發者與領域專家之間的共享詞彙，在對話、程式碼與檔案裡一致使用。在技能集裡，以純詞彙表的形式收在 CONTEXT.md——零實作細節、零規格。
ADR架構決策紀錄，在 docs/adr/ 底下。門檻很高：只在選擇難以逆轉、沒上下文會令人意外、且是真實取捨的結果時才提出。缺任何一個就沒有 ADR。
HITL / AFK（wayfinder）Human-in-the-loop vs away-from-keyboard。每張 wayfinder 票非 HITL（盤問、原型——需要活生生的一來一往）即 AFK（研究——代理獨自跑）。代理絕不自己回答 HITL 票上的問題。
單一視窗紀律（Context hygiene）讓主流程步驟 1–3（grill-with-docs → to-spec → to-tickets）留在同一個不中斷的上下文視窗——to-tickets 結束前不 compact、不清空——讓盤問、規格與票建立在同一份思考上。之後每個 implement 全新開始。
階段邊界（Phase boundary）（ask-matt）session 內兩個階段（盤問、實作、QA）之間的空檔。唯一能在我們的五個選項——Continue、/clear、/handoff、子代理、/compact——之間做選擇的地方：由上往下過樹，第一個「是」獲勝。階段中途沒有決策可做：繼續，或拆成子代理。
紅—綠迴圈（Red-green loop）寫一個失敗的測試（紅），加剛好足以通過的程式碼（綠），然後對下一個行為重複。只在綠時重構，絕不在紅時。tdd 與 implement 裡的引擎。

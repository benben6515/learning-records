ADRs — The Three-Criteria Gate

Where the glossary holds terms, ADRs hold decisions — almost none of them.

In Lesson 3 you asked the perfect follow-up: "if the glossary is devoid of implementation, where do I record that we use a bitmask for auth?" That's an ADR's job — if it clears a high bar. The whole skill of ADRs is restraint: most decisions you think deserve one… don't.

The one idea: an AND gate

Offer an ADR only when all three are true. The gate is AND, not OR.
Hard to reverse AND Surprising without context AND Real trade-off all three ⇒ ADR

Miss any one and you skip. Easy to reverse? You'll just reverse it — skip. Not surprising? Nobody will wonder why — skip. No real alternative? There's nothing to record beyond "we did the obvious thing" — skip. This is the antidote to ADR-sprawl: folders full of records nobody reads because they documented the obvious and the reversible.

The format itself is deliberately tiny — a title and 1–3 sentences:

# Auth permissions as a bitmask

permissionBits encodes each feature's access as a bit, so the menu
filter is a single bitwise AND instead of N role-membership lookups.
Chosen over a role list for O(1) filtering; the cost is that
adding a feature requires a reserved bit.

That's a real ADR. One paragraph. It exists so the next person doesn't "refactor" the bitmask into roles and quietly break the menu filter.

Your tangible win — does it clear the gate?

Two of these are situations many projects run into. For each, judge: ADR, or skip? Name which criterion fails if you'd skip.

  1. Auth is a bitmask (permissionBits), not a role list — because the menu filter is a bitwise AND.
  2. Auth moved to the new approach, the rest is still on the old one — old and new coexist, the migration isn't finished.
  3. We lint with eslint-config-standard.
  4. Router uses hash mode (createWebHashHistory), not history mode.

Hints: ask of each — would a future reader be surprised? is it costly to reverse? was there a real alternative? Reasoning in the reference's gate section; compare your calls after.

Terms vs decisions — the clean split

This closes the loop with Lesson 3. Two artefacts, two questions:

  • "What do we call this?" → CONTEXT.md (a term).
  • "Why did we choose this?" → an ADR (if it clears the gate).

So: "we call it permissionBits" is a term (glossary). "we made it a bitmask" is a decision (ADR). Same concept, two homes — and the bitmask decision only earns an ADR because it's hard to reverse, surprising, and a real trade-off.

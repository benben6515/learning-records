The Meta Skills: Teach & Writing for Agents

teach and writing-for-agents — the recursive layer.

Two productivity skills that sit off the main flow and operate on the skills set itself, or on your learning. They are the recursive layer.

/teach — learn over multiple sessions

This. Turns the current directory into a standing teaching workspace and teaches you one topic across many sessions — devising short, beautiful, interactive lessons tied to why you want to learn.

Parametric knowledge is untrusted teach does not teach from the model's own memory. Before it can teach, it gathers high-trust resources and grounds every claim in a citation. This workspace's RESOURCES.md is exactly that mechanism.

Stateful — sessions accumulate

The workspace remembers what you've learned, so each session picks up where the last left off rather than starting from scratch. It writes:

  • MISSION.md — the reason you're learning (grounds everything; if empty, teach's first job is to interview you until it isn't).
  • RESOURCES.md — vetted high-trust sources.
  • ./lessons/*.html — the numbered, self-contained lessons.
  • ./reference/*.html — compressed cheat-sheets, glossaries.
  • ./learning-records/*.md — what you've learned, ADR-style, used to judge what to teach next.
  • ./assets/* — reusable components (the shared stylesheet first).

Mission & the zone of proximal development

Every lesson hangs off the mission. From the mission and your learning records, teach computes your zone of proximal development — the next lesson should challenge you just enough, no more.

Storage strength, not fluency

The word to think with is storage strength — long-term retention — as opposed to fluency, the in-the-moment recall that feels like mastery but isn't. Teach deliberately builds the former through desirable difficulty: retrieval practice, spacing, and interleaving. Knowledge is taught first (where difficulty is the enemy), then skills are drilled through a tight feedback loop (where difficulty is the tool).

/writing-for-agents — the reference for authoring

The reference you write and edit skills against — the shared vocabulary and principles that make a skill predictable. (Renamed from writing-great-skills in 2026-07 and broadened: it now covers any document an agent reaches by a pointer — skills, AGENTS.md/CLAUDE.md, pointed-at docs.)

Predictability is the root virtue

A skill's job is to wrangle determinism out of a stochastic system, so the goal is not the same output every run but the same process. Predictability is the root virtue, and every design choice is judged against it — not against how clever, complete, or exhaustive the skill reads.

The concept it turns on: cognitive load

Every skill spends one of two loads (see Lesson 0012): model-invoked costs context load but fires on its own; user-invoked costs zero context load but you must remember it exists — that's cognitive load. Most of these skills are user-invoked, so cognitive load is the pressure the whole system is built to manage, and the cure when it piles up is a router skill (/ask-matt).

The other levers

  • Leading words — a compact concept already in the model's pretraining (tight, red, tracer bullet) that the agent thinks with while running the skill. Anchors execution in the fewest tokens.
  • Information hierarchy — the ladder from in-skill step → in-skill reference → external reference behind a context pointer. Progressive disclosure is the move down that ladder so the top stays legible.
  • Pruning — single source of truth, relevance, and the no-op test applied sentence by sentence, against sediment and sprawl.
  • Failure modes — premature completion, duplication, sediment, sprawl, no-op — to diagnose a skill that isn't behaving.

四種失敗模式

AI 工作階段出錯的四種方式——以及各自對應的修復技能。

Matt Pocock 技能集裡的每一項技能，都是為了修復某一種「AI 寫程式工作階段出錯的方式」。在學任何單一技能之前，先學這四種——它們是整門課其餘部分所依據的地圖。

四種

  1. 失準（Misalignment）——代理沒做你要的事。你以為它懂了；產出證明它沒懂。這是最常見的失敗。
  2. 冗長／沒有共用語言（Verbosity / no shared language）——該用一個字的地方，代理卻用了二十個字，因為沒人教過它這個專案的行話。
  3. 程式碼不能跑（The code doesn't work）——你們已對齊，但產出還是壞的。沒有任何回饋迴圈告訴代理，它的程式碼實際上做了什麼。
  4. 爛泥球（A ball of mud）——程式庫難以變更。代理會加速熵增，所以少了刻意的設計照護，它只會快速惡化、複合。
這個模式 這些沒有一個是聰明度問題。每一個都是溝通或回饋問題。修復方法都是借用自數十年軟體工程的紀律——窮追不捨地訪談、把語言寫下來、執行程式碼、投資設計——把它們做成可重複的技能。

一種失敗，一個修復

失敗修復技能植基於
失準/grill-me、/grill-with-docs《The Pragmatic Programmer》
沒有共用語言/grill-with-docs 建立 CONTEXT.md + ADR《Domain-Driven Design》（Evans）
程式碼不能跑/tdd、/diagnosing-bugs《The Pragmatic Programmer》
爛泥球/to-spec、/improve-codebase-architecture、/codebase-designXP（Beck）、Ousterhout

當你能把任何情況歸入這四種之一，你就知道該抓哪個技能了。整場遊戲就是這樣。

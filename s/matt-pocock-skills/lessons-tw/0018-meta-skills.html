後設技能：teach 與 writing-great-skills

teach 與 writing-great-skills——那個遞迴層。

兩個生產力技能，它們坐在主流程之外，對技能集本身、或對你的學習來運作。它們是那個遞迴層。

/teach——跨多次 session 學習

就是這門課。它把當前目錄變成一個常設的教學工作區，並跨許多次 session 教你一個主題——設計出簡短、漂亮、互動的課，繫於你為何想學。

參數知識不可信 teach 不從模型自己的記憶裡教。在它能教之前，它會收集高信任資源，並把每一項主張都奠基於一則引用。本工作區的 RESOURCES.md 正是那個機制。

有狀態——session 會累積

工作區記得你學到哪裡，所以每次 session 都從上次離開之處接續，而非從零開始。它寫下：

  • MISSION.md——你為何而學（奠定一切；若為空，teach 的第一個任務就是訪談你，直到它不空）。
  • RESOURCES.md——審核過的高信任來源。
  • ./lessons/*.html——編號、各自獨立的課。
  • ./reference/*.html——壓縮後的小抄、詞彙表。
  • ./learning-records/*.md——你學到了什麼，ADR 風格，用來判斷下一步教什麼。
  • ./assets/*——可重複使用的元件（首先是共用的樣式表）。

任務與近側發展區

每一堂課都掛在任務之下。從任務與你的學習紀錄，teach 算出你的近側發展區（zone of proximal development）——下一堂課該挑戰你恰到好處，不多不少。

要的是儲存強度，不是流利度

用來思考的那個詞是儲存強度（storage strength）——長期記憶——而不是流利度（fluency），那種當下的回憶，感覺像精通、其實不是。teach 刻意透過「合意難度」來建立前者：提取練習、間隔、交錯。知識先教（此處難度是敵人），技能再透過緊密的回饋迴圈來鍛鍊（此處難度是工具）。

/writing-great-skills——撰寫技能的參考

你撰寫與編輯技能時所依的參考——讓一個技能變得可預測的那套共用詞彙與原則。

可預測性是根本美德

一個技能的任務，是從一個隨機系統裡擰出確定性，所以目標不是每次跑出一樣的輸出，而是一樣的過程。可預測性是根本美德，每一個設計選擇都拿它來評判——而不是拿這個技能讀起來多聰明、多完整、多詳盡來評判。

它所依的核心觀念：認知負荷

每個技能花的是兩種負荷之一（見第 0017 課）：模型觸發花上下文負荷，但會自行觸發；使用者觸發不花上下文負荷，但你必須記得它存在——那就是認知負荷。這些技能大多是使用者觸發的，所以認知負荷是整套系統被設計來管控的壓力，而它堆積起來時的解藥是一個路由器技能（/ask-matt）。

其他幾根操縱桿

  • 主導詞（leading words）——已存在於模型預訓練裡的精簡概念（tight、red、tracer bullet），代理在跑技能時拿來思考。用最少的 token 錨定執行。
  • 資訊層級——從「技能內步驟 → 技能內參考 → 一個上下文指標背後的外部參考」這道階梯。漸進揭露（progressive disclosure）就是沿這道階梯往下走的動作，好讓頂層保持可讀。
  • 修剪——單一真實來源、相關性，以及逐句套用的「no-op 測試」，對抗沉積（sediment）與蔓延（sprawl）。
  • 失敗模式——過早完成、重複、沉積、蔓延、no-op——用來診斷一個行為異常的技能。

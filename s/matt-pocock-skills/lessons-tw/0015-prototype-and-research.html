原型與研究

兩個能快速回答問題、再把結果餵回主流程的獨立工具。

兩個獨立工具：快速回答一個問題，再把結果餵回主流程。

/prototype——從第一天起就是拋棄式

一個小小的、用完即丟的程式，它唯一的任務是回答一個設計問題：這個狀態模型對不對勁，或這個 UI 該長什麼樣。

它沒有測試、沒有超出「能跑」所需的錯誤處理、沒有抽象、沒有持久化。重點是快速學到一件事，然後刪掉它。你一開始硬化它，就不再是在做原型了。

兩條分支——先挑，再做

挑錯分支會浪費掉整個原型，所以問題先來：

問題形狀
「這個邏輯／狀態模型對不對勁？」單一可分享的 HTML 檔——自由操作按鈕，加上分頁式的導引走讀——把狀態機推過那些尷尬的案例，非開發者也能上手操作。
「這個該長什麼樣？」在同一條路由上的數個截然不同的 UI 變體，從一條浮動工具列切換，讓你比較真實的渲染、而非憑空想像。

兩條分支都把狀態留在記憶體裡、用一道指令跑起來，並在每一步顯露完整狀態。

把原型留作主要來源

那個答案——結論加上它所敲定的問題——才是你持久捕捉下來的東西（一則 commit 訊息、一份 ADR、一個 issue）。而原型本身就是一份主要來源——答案所來自的那份可執行證據。

它住在哪裡 它不屬於主分支：沒有測試，沒有要維護的東西。但也別毀了它。把它留在拋棄式分支上——離開主分支、永不合併——並在實作 issue 上留一個指向它的上下文指標。主分支保持乾淨；那份原始探索則在一點之遙。

不適用於：若某個已建好的東西行為異常，而你需要找出為什麼，用 /diagnosing-bugs。原型探索的是「要建什麼」，而不是「已建好的東西為何壞了」。

/research——委派出去的跑腿活

它透過閱讀「擁有答案的那些來源」來回答一個問題，並留下一份帶引用的 Markdown 檔。它只從主要來源工作——官方文件、原始碼、規格、第一方 API——絕不用對它們的二手轉述，所以它存下的東西都追溯得到某個權威出處。

定義動作：背景代理

閱讀是以背景代理執行的。你繼續工作；它跑到一邊，把每一項主張追回它的主要來源，並把單一份帶引用的 Markdown 檔丟進 repo 存這類筆記的地方。研究是你委派出去的跑腿活，而不是你外包出去的思考——你拿回來的是一份可以回應、並附有來源的文件。

餵養思考，不取代思考 research 產出的那份檔案，是要在 /grill-with-docs 帶進主流程的東西——研究餵養思考，它不取代思考。

不適用於：想用訪談而非閱讀來磨利計畫，用 /grilling；想用拋棄式程式碼探索「要建什麼」，用 /prototype。

向老師提問 卡住了或好奇？儘管追問——任何不清楚的地方都可以問。

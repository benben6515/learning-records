Matt Pocock Skills Catalog

Categorised per the official repo (mattpocock/skills), with one-line descriptions. The skill name is the invocation name.

28 stable skills across four categories — Engineering, Productivity, Misc, and Personal — plus in-progress and deprecated ones listed at the end. Each is authoritatively defined by its own SKILL.md.

This workspace teaches the spec-driven spine among them — ask-matt → grill-with-docs → to-spec → to-tickets → implement — documented by domain-modeling and consumed by improve-codebase-architecture. See the workflow map.

User-invoked: fires only when you type it (disable-model-invocation). Model-invoked: the model can grab it on trigger words autonomously.

Engineering (day-to-day code work)

User-invoked

SkillOne-liner
ask-mattAsk “which skill or flow fits my situation” — the entry router for every user-invoked skill in the repo.
grill-with-docsA relentless interview that sharpens a plan or design while building the project's domain model in place (updating CONTEXT.md and ADRs).
triageMoves issues through a state machine of triage roles (categorise, verify, grill if needed), writing agent-ready briefs.
improve-codebase-architectureScans the codebase for deepening opportunities, presents them as a visual HTML report, then grills you on whichever you pick.
setup-matt-pocock-skillsSets up this repo's issue tracker, triage-label vocabulary, and domain-doc layout; run once per repo.
to-specSynthesizes the current conversation into a spec and publishes it to the issue tracker — no interviewing, just what's already settled.
to-ticketsBreaks a plan/spec/conversation into tracer-bullet tickets, each declaring its blocking edges, published to the configured tracker.
implementImplements work from a spec or set of tickets, driving /tdd at pre-agreed seams and closing with /code-review before committing.
wayfinderPlans a chunk of work too big for one agent session as a map of decision tickets on the issue tracker, resolving them one at a time until the way is clear.

Model-invoked

SkillOne-liner
prototypeBuilds a throwaway prototype to answer a design question: verify state/logic via a terminal program, or explore UI via togglable variants.
diagnosing-bugsA disciplined loop for hard bugs and performance regressions: reproduce → minimise → hypothesise → instrument → fix → regression-test.
researchInvestigates a question against high-trust primary sources, capturing findings as a cited Markdown file; runs as a background agent.
tddTDD via the red-green-refactor loop; build features or fix bugs one vertical slice at a time.
domain-modelingProactively builds and sharpens the project's domain model — challenges terminology, stress-tests with scenarios, updates CONTEXT.md and ADRs inline.
codebase-designThe shared discipline and vocabulary for designing deep modules: small interfaces, clean seams, testable through the interface.
code-reviewReviews the diff since a fixed point along two axes — Standards (repo conventions + Fowler smell baseline) and Spec (faithful to the originating issue/PRD) — via parallel sub-agents.
resolving-merge-conflictsWorks through in-progress git merge/rebase conflicts hunk by hunk, resolving per each side's original intent, then completes the operation — never --abort.

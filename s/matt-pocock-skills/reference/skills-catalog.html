Matt Pocock Skills Catalog

Categorised per the official repo (mattpocock/skills), with one-line descriptions. The skill name is the invocation name.

29 stable skills across three promoted categories — Engineering, Productivity, and Misc — plus in-progress and deprecated ones listed at the end. Each is authoritatively defined by its own SKILL.md.

This workspace teaches the spec-driven spine among them — ask-matt → grill-with-docs → to-spec → to-tickets → implement — documented by domain-modeling and consumed by improve-codebase-architecture. See the workflow map.

User-invoked: fires only when you type it (disable-model-invocation); its job is to orchestrate. Model-invoked: the model can grab it on trigger words autonomously; it holds the reusable discipline.
A user-invoked skill may invoke model-invoked skills, but never another user-invoked one.

Engineering (day-to-day code work)

User-invoked

SkillOne-liner
ask-mattAsk “which skill or flow fits my situation” — a router over the skills in this repo.
grill-with-docsA grilling session that also builds your project's domain model, sharpening terminology and updating CONTEXT.md and ADRs inline.
triageMoves issues through a state machine of triage roles; produces agent-ready issues with agent briefs.
improve-codebase-architectureScans the codebase for deepening opportunities, presents them as a visual HTML report, then grills you on whichever you pick.
setup-matt-pocock-skillsConfigures this repo for the engineering skills (issue tracker, triage labels, domain doc layout). Run once per repo.
to-specTurns the current conversation into a spec and publishes it to the issue tracker — no interview, just synthesizes what you've already discussed.
to-ticketsBreaks any plan, spec, or conversation into tracer-bullet tickets, each declaring its blocking edges — text in a local file, or native blocking links on a real tracker.
implementBuilds the work described by a spec or set of tickets, driving /tdd at pre-agreed seams and closing with /code-review before committing.
wayfinderPlans a chunk of work too big for one agent session as a shared map of decision tickets on the issue tracker, resolving them one at a time until the way is clear.

Model-invoked

SkillOne-liner
prototypeBuilds a throwaway prototype to answer a design question: a single shareable HTML file for state/logic questions, or radically different UI variations toggleable from one route.
diagnosing-bugsDisciplined diagnosis loop for hard bugs and performance regressions: build a feedback loop that goes red on this bug → minimise → hypothesise → instrument → fix → regression-test.
researchInvestigates a question against high-trust primary sources and captures the findings as a cited Markdown file in the repo; runs as a background agent.
tddTest-driven development with a red-green-refactor loop. Builds features or fixes bugs one vertical slice at a time.
domain-modelingActively builds and sharpens the project's domain model: challenges terms against the glossary, stress-tests with edge-case scenarios, updates CONTEXT.md and ADRs inline.
codebase-designShared discipline and vocabulary for designing deep modules: a lot of behaviour behind a small interface, placed at a clean seam, testable through that interface.
code-reviewTwo-axis review of the diff since a fixed point — Standards (repo conventions + Fowler smell baseline) and Spec (faithful to the originating issue/spec) — run as parallel sub-agents.
resolving-merge-conflictsWorks through an in-progress git merge/rebase conflict hunk by hunk, resolving by intent traced to each side's primary source, then finishes the operation — never --abort.
wizardmovedGenerates an interactive bash wizard that walks a human through steps only they can perform: provisioning infrastructure, credentials or CI secrets, unfamiliar third-party dashboards, one-off migrations or cutovers.

兩種債與一個陷阱

loop 不會刪掉你——被放大的 comprehension debt、orchestration tax 與 cognitive surrender。

第 01 課那句話要認真對待：loop 改變了工作，沒有把你從工作中刪掉。而且有三個問題會隨著 loop 變強而更尖銳，不是更輕鬆。這堂課把它們一次講清楚：兩種「債」、一個「陷阱」，外加一種「稅」。源文件的定義很精準——我們照著走。

同一個 loop，相反結果。loop 分不出來——你分得出來。「Build the loop. Stay the engineer.」

債一：Intent debt（意圖債）

每個 session 都冷啟動，缺漏的意圖被「自信的猜測」填滿。還法：skills——把慣例、build、「我們不這樣做」寫一次、每次讀（第 05 課）。這是 loop 還沒跑就先欠下的債。

債二：Comprehension debt（理解債）

這是真正會咬人的債。理解債＝repo 實際內容與「你真正理解多少」的差距。loop 出貨愈快、寫了愈多「你沒寫的程式碼」，這條差距就拉得愈開。還法只有一個：去讀它寫了什麼。不讀，債就只增不減。

關鍵 「做完了」是個主張，不是證明。loop 跑得愈快，你「以為自己懂」和「實際懂多少」的落差就愈危險。

陷阱：Cognitive surrender（認知棄守）

放任 loop 跑、自己不再有意見——這個狀態很舒服，也很危險。源文件講得最到位的一句：「用判斷力設計 loop 是解藥；用 loop 逃避思考是加速器。同一個動作，相反結果。」

兩個人跑一模一樣的 loop，一個用它加速「自己深刻理解」的工作；另一個用它逃避理解工作。loop 分不出來——你分得出來。這就是為什麼 comprehension debt 會不斷累積：棄守，是它的供給。

稅：Orchestration tax（編排稅）＋ token 成本

前兩個是「你跟 repo 的關係」，這個是「你跑 loop 的成本」。

編排稅＝協調並行 agent 的人力成本：review 頻寬、merge 衝突、context 切換。worktree 拿掉機械性的碰撞，但你（人）仍是並行數的天花板——能同時吸收幾個 loop，是人的限制，不是工具的。

token 成本有個反直覺的乘數：cadence 是線性乘數——5 分鐘跑一次 vs 一天一次，是一天 288 倍的 run。CI sweeper 每 15 分鐘跑、若每次都「全跑」，一天可以燒到 ~5M tokens。解法：early-exit——只在 state 說「有可做的」時才 spawn sub-agent；空的 watchlist 就在 5k tokens 內退出。

四件事怎麼串起來

名稱是什麼還法／解法
Intent debt冷啟動，意圖被自信猜錯skills（第 05 課）
Comprehension debtrepo 內容 vs 你懂多少的差距讀它寫了什麼
Cognitive surrender放任跑、不再有意見用判斷力設計 loop，別用它逃避思考
Orchestration/cost tax並行協調成本＋cadence 線性燒 tokenworktree＋early-exit＋預算上限

讀法：前兩個（intent、comprehension）是你要主動還的債；cognitive surrender 是讓債變成致命的陷阱；orchestration/cost 是持續在付的稅。loop 的經營，就是在這四件事上保持清醒。

何時該慢下來／停／殺掉 慢下來：預算週中破 80%、triage 誤報率 >30%、同一項 48 小時內被升級 2 次以上。暫停：production 事件進行中、schema migration 進行中、關鍵 reviewer 不在還開著 auto-merge。殺掉：成本 > 價值連續兩週、團隊把所有通知靜音。

帶走的一句話

loop 不會刪掉你——它放大你。理解債會不會吃掉你，取決於你願不願意讀、願不願意保持意見。最後一堂課看怎麼把這些觀念落地成可複製的生產模式。

問你的老師 「我現在用 agent，理解債大概欠了多少？」「我有沒有在 cognitive surrender？怎麼自查？」「我的工作中，哪一段最適合用 loop 加速理解、而不是逃避理解？」——任何不清楚的都可以問。

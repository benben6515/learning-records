七個 Patterns 與 Loop Ready score

把觀念落地成可複製的生產 loop，以及「能不能上線」的評分。

這是最後一堂。前面七課建立的是心智模型——loop 是什麼、六個零件、兩根支柱、自主等級、風險。這堂課把它們落地：可複製的生產模式（patterns），以及一個告訴你「能不能上線」的Loop Ready 分數。學完這堂，你就有詞彙看懂任何一個真實 loop。

Pattern 是「可複製的生產 loop」；Loop Ready score 是「你能不能放手」的客觀量尺。先挑一個 pattern，從 L1 開始。

什麼是 pattern

Pattern 是一個可複製的生產 loop——每個都有自己的節奏（cadence）、自主等級、token 成本。挑選原則很簡單：一個顧慮，挑一個主 loop；重疊的 loop 需要協調（別讓它們在同一小時搶同一條 branch）。

Loop Ready score：0–100 的客觀量尺

「能不能放手」不是感覺問題。loop-audit 給你的專案打一個 0–100 的 Loop Readiness 分數，背後是 20 多個信號。幾個關鍵事實：

  • 它把分數對應到自主等級——L0/L1/L2/L3 各自對應設計清單的不同段落（第 06 課那張表）。
  • 最高權重的信號是 verifier 與 state——兩者各 14 分，並列所有信號裡最高。這正是第 03、04 課說的「兩根支柱」的量化證明。
  • L3 被機械性擋住，直到 loop-budget.md＋loop-run-log.md＋LOOP.md 預算段落就位。
  • 自主等級不是單向棘輪——可以、也應該往下退。
分數高，不代表就能放手 有個故事：一個團隊 loop-init＋loop-audit 衝到 92 分，report-only 的 Daily Triage 也真的看出了價值。然後他們在第 6 天把它升級成每 15 分鐘跑的 CI sweeper——卻沒有獨立的 verifier、沒有 branch 白名單、也沒有硬性的每日 token 上限。分數高是必要，不是充分。

設計清單上的紅旗（看到就停修）

  • 同一個 PR 已被自動修復 >3 次沒有進展。
  • Verifier 跟 implementer 是同一個 session。
  • 沒有 state 檔——loop 每次 run 都失憶。
  • 不管有沒有發現，每次 run 都發通知。
  • 開了 auto-merge 卻沒有 path 白名單。

帶走的一句話

你現在有了完整的詞彙：能講清楚 loop 是什麼、harness 與 loop 的差別、六個 primitives、兩根支柱、L1→L2→L3、四種風險，以及七個 patterns 與 Loop Ready score。心智模型到此建立完成——這是「動手」階段的起點，不是終點。下一階段（scaffold 你的第一個 loop、採用評估）就在這個模型之上展開。

課程完成——問你的老師 模型建好了，接下來是你要決定的方向：「我想挑一個 pattern（例如 Daily Triage），動手 scaffold 我的第一個 loop——從哪裡開始？」「我想先做採用評估：這套適不適合我的工作流程？」「哪個觀念我還想再深入？」心智模型階段到此完成，下一步由你決定。

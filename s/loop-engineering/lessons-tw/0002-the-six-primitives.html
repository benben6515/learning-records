六個 Primitives（＋Memory）：loop 的零件詞彙表

把 loop 拆成六個零件——每個都修好一個會讓 loop 壞掉的洞。

上一課你看過那張全貌表：loop 不是一道長 prompt，而是六個零件組成的小系統。這堂課把它們一個個拆開。讀法很簡單——每個 primitive 都對應一個「沒有它，loop 就會在這裡壞掉」的洞。先認得零件與它修好的洞，後面幾堂課（maker/checker、state、skills）再分別往深裡走。

六個 primitives，六個洞。學它們，就是在學「loop 會在哪裡失靈」。

1. 排程（Scheduling）— loop 的心跳

沒有排程，你只是跑了一次 agent，不是 loop。排程把「一次 run」變成「在時間上反覆發生的 run」，所以它是 loop 的心跳。形式很多：/loop（Grok）、Claude Code 的排程任務／cron、GitHub Actions、/goal（跑到某個可驗證條件成立才停）。要留意的屬性：間隔多久、能不能立刻觸發、recurring 還是一次性、重啟後還在不在（durable）。

它修好的洞 沒有心跳 → 沒有「在時間上編排」，就退化成一次性 run。

2. Worktree — 並行不互踩

兩個 agent 同時改同一批檔案，就是 merge hell。Git worktree 給每個 agent 一個獨立的工作目錄——共享歷史，但不共享工作區。用完要清理：任務結束或交回給人，就把那棵 worktree 刪掉。loop-worktree 這類 CLI 把這件事機械化：每次嘗試一棵 worktree、記在 manifest 裡、被拒或升級時清掃。

它修好的洞 並行 agent 互踩檔案 → 給各 agent 一個隔離的 checkout，並行而不混亂。

3. Skills — 意圖的記憶

每次 session 都冷啟動；你沒寫下來的意圖，會被 agent「自信的猜測」填滿——這叫 intent debt（意圖債）。Skill 是還債的單位：通常是一個 SKILL.md，封裝專案慣例、build/test/lint 指令、review 標準、領域知識，以及「我們不這樣做，因為那次事故」。沒有 skill，loop 每次都從零重新推導一切。Skill 也是重用的單位——打包成 plugin，跨 repo、跨團隊共用。

它修好的洞 冷啟動 + 缺漏意圖被自信猜錯 → 把意圖寫在外面，每次讀，付清 intent debt。

4. Connectors（MCP）— 從評論員到操作員

只會讀檔案系統的 loop，最多是個評論員。Connectors 讓它變成操作員：讀寫 Linear／Jira ticket、貼 Slack／Discord、查資料庫或內部 API、在 GitHub 開 branch 和 PR、觸發部署。MCP（Model Context Protocol）已經成為共同底層——為一個工具寫的 connector，常常換個工具也能用。

它修好的洞 loop 只能「說」不能「做」→ 接上真實工具，它才能動到世界。

5. Sub-agent（maker/checker）— 寫的人不批改自己

這是「讓 loop 可靠」最重要的一個結構原則。寫程式的那個 agent，對自己的程式碼是個差勁的裁判。第二個 agent（有時用更強的模型，永遠用不同的指令）負責驗證。常見分工：Explorer → Implementer → Verifier；Implementer → Security reviewer；Implementer → Test writer + runner。在 unattended 的 loop 裡，那個 verifier 正是「讓你（人）敢走開」的本錢。/goal 也用了同一招：用另一個模型來判斷停止條件成不成立。

它修好的洞 實作者批改自己的作業 → 分出一個 verifier；這是結構性事實，不是模型不夠強。

6. State（記憶）— 進度的脊椎

模型跨 session 沒有長期記憶。loop 必須讀寫一個持久的東西：repo 裡的 STATE.md／LOOP-STATE.json、Linear board 的一段、GitHub Project、或資料庫一列。好的 state 回答三件事：我們現在在做什麼？上次試了什麼、結果如何？什麼在等人？ 這個 state 檔，常常是 loop 產出最重要的單一成品。

它修好的洞 模型會忘 → 把進度落在磁碟上；跨 session 才接得起來。

兩種記憶，別搞混

上面有兩個看起來都像「記憶」的零件，它們記的是不同的東西：

記的是回答
Skills「意圖」的記憶我們要什麼、怎麼做、什麼不做
State「進度」的記憶我們做到哪、試過什麼、卡在哪

合起來，loop 才有「想得起來的過去」與「不會忘的標準」。這也是為什麼課程寫「六個 primitives（＋Memory）」——State 那一格就是那個 +Memory。

它們怎麼組起來：生長路徑

你不必一次到齊。最小可行的 loop 從三件最小的事開始，其餘 primitive 在「前一個版本證明了價值、也暴露了壞掉的方式」之後，才一個個加上去：

最小可行 loop
排程+ triage skill+ state 檔
開始改東西了 →
＋ Worktree
要自主跑了 →
＋ Sub-agent 驗證（maker/checker）
要推 ticket / PR 了 →
＋ Connectors（MCP）
最好的 loop 是「長」出來的，不是一次蓋好——每加一個零件，都先看過前一版怎麼壞的。

帶走的一句話

記住這六個零件，不如記住它們各自修好的那個洞：沒有心跳、並行互踩、意圖被猜、只能說不能做、自己批改自己、轉身就忘。loop engineering 的可靠度，就是把這六個洞一個個補起來的結果。接下來三堂課，會挑三個最關鍵的洞深入——先從 maker/checker 開始。

問你的老師 把這六個零件對照你自己的工具看看，例如：「我用 opencode，這六個哪些我已經有、哪些還沒？」「skills 跟我現在用的 AGENTS.md 是同一件事嗎？」「worktree 我從哪裡開始？」「我的 loop 缺哪個洞最危險？」——任何不清楚的都可以問。

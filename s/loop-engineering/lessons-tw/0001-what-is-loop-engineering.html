Loop Engineering 是什麼：別再自己 prompt

從「逐句 prompt agent」升級成「設計會驅動 agent 的系統」。

你現在大概是這樣用 agent 的：打一句、讀回應、再打下一句，全程握著它。Boris Cherny（Anthropic Claude Code 負責人）說他已經不這樣做了——「我不再 prompt Claude 了。我有 loop 在跑、由它們去 prompt Claude 並決定要做什麼。我的工作是寫 loop。」這門課要講的，就是把這句話變成你能用的觀念。

Loop engineering＝取代那個「自己 prompt agent」的你。你設計系統，系統去戳 agent。 —— Cobus Greyling / Addy Osmani

一個概念：loop 是「遞迴目標」

把 loop 想成一個遞迴目標（recursive goal）：你定義一個目的，agent 用 sub-agent 與外部記憶體反覆迭代，直到完成，或直到它把事情交回給你。關鍵在於——你把整件事設計一次，之後不再逐句 prompt 那些步驟。系統自己去發現工作、分派、驗證、寫回狀態、決定下一步。

這跟「寫一個 prompt」是不同層的事。一年前想做 loop，你得自己維護一堆 bash 腳本；現在這些零件已經內建在工具裡（Claude Code、Codex、Grok、opencode），所以 loop 的「形狀」漸漸跨工具通用——你設計的 loop 不會綁死在某個工具上。

關鍵區別：Harness vs Loop

要懂 loop，先分清楚它和「harness」的差別——這是很多人混淆的地方：

概念是什麼解決的問題
Harness（馴具）單一 agent、單次 session 的環境設定：工具、context、權限、規則「這一次 run」要跑得好
Loop（迴圈）harness ＋ 排程 ＋ 狀態 ＋ 驗證鏈「在時間上反覆編排」這些 run

一句話：harness 是單次 session 的沙盒；loop 是「排程並編排 harness 跑」的系統。Loop 在 harness 的上一層樓——它跑在計時器上、生出小幫手、自己餵自己。

全貌：六個 Primitives（＋Memory）

一個能 unattended 跑的 loop，不是一道長 prompt，而是六個零件組成的小系統。先認全貌，後面幾堂課各深入一個：

Primitive在 loop 裡的工作
排程 / 自動化心跳。沒有排程，就只是一次性 run。形式：/loop、cron、GitHub Actions、/goal。
Worktree隔離的 git checkout，讓多 agent 並行不互踩檔案。
Skills意圖的持久記憶（SKILL.md）：慣例、build、與「我們不這樣做」。
Connectors（MCP）讓 loop 動到真實工具：開 PR、更新 ticket、貼 Slack。
Sub-agent（maker/checker）一個寫、另一個驗。實作者絕不評分自己的作業。
＋ State（記憶）跨 session 的持久脊椎（STATE.md）。模型會忘，repo 不會。

最小可行 loop 通常從 排程 ＋ 一個 triage skill ＋ 一個 state 檔 開始，再依證明的價值一個個加上去。

最重要的一句：loop 不會刪掉你

Loop 改變了工作，沒有把你從工作中刪掉。而且有三個問題會隨著 loop 變強而更尖銳，不是更輕鬆：

  1. 驗證仍是你的責任。 無人看管的 loop，也在無人看管地犯錯。「做完了」是個主張，不是證明——你仍要讀進 repo 的東西。
  2. 理解債長更快。 loop 出貨愈快，repo 內容與「你真正懂多少」的差距就拉得愈開。
  3. 認知棄守的舒適陷阱。 放任 loop 跑、自己不再有意見，很舒服也很危險。
同一個 loop，相反結果 兩個人能跑一模一樣的 loop，得到完全相反的結果。一個用它加速「自己深刻理解」的工作；另一個用它逃避理解工作。Loop 分不出來。你分得出來。—— Addy Osmani：「Build the loop. Stay the engineer.」

帶走的一句話

槓桿點已經從「寫好單一 prompt」移到「設計會編排 agent 的控制系統」。Cherny 的意思不是工作變簡單了，而是施力的位置變了。接下來的課，會把上面那六個零件一個個講清楚。

問你的老師 哪裡卡住、或想再追問？例如：「六個 primitives 我先深入哪個？」「我自己用 opencode，能對應到哪些零件？」「/goal 和 /loop 到底差在哪？」——任何不清楚的地方都可以問。

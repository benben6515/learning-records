Skills：把 intent 寫在外面

付清 intent debt——把慣例、build、與「我們不這樣做」寫一次，每次讀。

前三堂課講了 loop 的零件與兩根支柱。這堂課回到第 3 個 primitive——skills。源文件稱它為「意圖的持久記憶」。上一課的 state 記的是「做到哪」（進度）；skills 記的是「要什麼、怎麼做、什麼不做」（意圖）。沒有它，loop 每次都從零重新推導——這就是 intent debt（意圖債）。

每次 session 都冷啟動；你沒寫下來的意圖，會被「自信的猜測」填滿。Skill 是還債的單位。

問題：意圖債是怎麼欠下的

每個 session 都冷啟動。你心裡有、卻沒寫下來的東西——「我們用 pnpm 不用 npm」「這個欄位不能是 null」「別動那個檔，因為上次踩過雷」——agent 一概不知道。它不會停下來問，而是用自信的猜測把空缺填滿。猜對是運氣，猜錯你就要收拾。每次 run 都重新欠一次這筆債。

解法：一個 SKILL.md，寫一次、每次讀

Skill 通常是一個 SKILL.md（可附腳本與參考），封裝：

  • 專案慣例——用哪個套件管理器、命名規則、目錄結構。
  • build/test/lint 指令——確切指令，不是「跑一下測試」。
  • review 標準——什麼算「可以 merge」。
  • 領域知識——業務規則、資料模型。
  • 「我們不這樣做，因為那次事故」——這是精華。
skill 不只是指令，是傷疤 「我們不這樣做，因為 X 事故」這一類條目，是把制度記憶（scar tissue）編進 skill。它不是教 agent 怎麼做，而是教它別重蹈覆轍。這是 skill 最有價值、也最難從程式碼本身推導出來的部分。

沒有 skill，loop 每次從零推導

源文件講得很直白：沒有 skill，loop「每次都從零重新推導一切」。同樣的慣例、同樣的 build 指令、同樣的「別踩雷」，每一次 run 都重新猜一遍。Skill 把這些寫一次、每次讀，把重複的猜測變成可靠的預設。

triage skill：大多數 loop 的第一個 skill

最小可行 loop 是「排程 ＋ 一個 triage skill ＋ 一個 state 檔」。triage skill 是那個「判讀工作、決定要動什麼」的 skill，而且它的輸出格式要收得很緊——這樣下游才好解析。設計清單還提醒：skill 的描述要「無聊且具體」，自動觸發才會準。

skill 也是重用的單位

Skill 不只還你一個 repo 的債——把它打包成 plugin，就能跨 repo、跨團隊共用。一個團隊踩過的雷，編成 skill 後，所有 loop 都不必再踩一次。

兩種記憶，最後收攏

記的是回答沒有它會
Skills意圖要什麼、怎麼做、什麼不做每次冷啟動重猜（intent debt）
State進度做到哪、試過什麼、卡在哪每次失憶接不起來

兩者合起來，loop 才有「不會忘的標準」與「想得起來的過去」。Phase B（讓 loop 真的可靠）到這裡講完——下一課進入 Phase C：自主等級。

對照你自己的工具 你現在用的 AGENTS.md，本質上就是一種「把專案慣例寫在外面、每次讀」的檔案——功能上接近一個共用的 skill。差別在於：skill 是結構化、可觸發、可重用的單位（有自己的描述、輸出格式、能被打包）。觀念是同一條：把意圖從「你腦裡」搬到「磁碟上」。

帶走的一句話

Skill 是把「你以為大家都知道、其實只有你知道」的東西寫成檔案。付清 intent debt 的方法很樸素：寫一次，每次讀。

問你的老師 「我現在的 AGENTS.md 裡，哪些是慣例、哪些是『因為踩過雷』？」「如果要把它拆成一個個 skill，我會從哪個開始？」「triage skill 的輸出格式為什麼要收緊？」——任何不清楚的都可以問。

接下來 → 第 06 課：自主等級 L1 → L2 → L3——Phase C 開始，先 report-only，再 assisted，最後 unattended。

Two Debts and a Trap

The loop doesn't delete you — amplified comprehension debt, orchestration tax, and cognitive surrender.

Take seriously the line from Lesson 01: the loop changes the work; it doesn't delete you from it. And three problems actually get sharper as the loop gets better, not easier. This lesson lays them out at once: two "debts," one "trap," plus a "tax." The source definitions are precise — we follow them.

Same loop, opposite outcomes. The loop doesn't know the difference — you do. "Build the loop. Stay the engineer."

Debt one: Intent debt

Every session is a cold start; missing intent gets filled with confident guesses. The pay-down: skills — write conventions, build, and "we don't do it this way" once, read every run (Lesson 05). It's debt you owe before the loop even runs.

Debt two: Comprehension debt

This is the one that bites. Comprehension debt = the gap between what exists in the repo and what you actually understand. The faster the loop ships code you didn't write, the wider the gap opens. The only pay-down: read what the loop made. Don't read, and the debt only grows.

The key "Done" is a claim, not a proof. The faster the loop runs, the more dangerous the gap between "what you think you understand" and "what you actually do."

The trap: Cognitive surrender

Letting the loop run while you stop having opinions — that state is comfortable, and dangerous. The source puts it best: "Designing loops with judgment is the cure; using loops to avoid thinking is the accelerant. Same action, opposite outcome."

Two people run the exact same loop: one uses it to move faster on work they understand deeply; the other uses it to avoid understanding the work. The loop can't tell the difference — you can. That's why comprehension debt keeps accumulating: surrender is its supply.

The tax: Orchestration tax + token cost

The first two are about "your relationship with the repo"; this one is "the cost of running loops."

Orchestration tax = the human cost of coordinating parallel agents: review bandwidth, merge conflicts, context switching. Worktrees remove the mechanical collisions, but you (the human) remain the ceiling on parallelism — how many loops you can absorb at once is a human limit, not a tool limit.

Token cost has a counter-intuitive multiplier: cadence is linear — running every 5 minutes vs once a day is 288× the runs per day. A CI sweeper running every 15 minutes, if every run is "full," can burn ~5M tokens/day. The fix: early-exit — spawn sub-agents only when state says "there's something actionable"; an empty watchlist exits in under 5k tokens.

How to read it: the first two (intent, comprehension) are debts you actively pay; cognitive surrender is the trap that turns debt fatal; orchestration/cost is the tax you keep paying. Operating a loop means staying awake on all four.

When to slow down / pause / kill Slow down: budget >80% mid-week, triage false-positive rate >30%, same item escalated 2+ times in 48h. Pause: production incident in progress, schema migration underway, key reviewer OOO with auto-merge on. Kill: cost > value for 2 consecutive weeks, team mutes all notifications.

One sentence to take away

The loop doesn't delete you — it amplifies you. Whether comprehension debt eats you depends on whether you'll read, and keep having opinions. The final lesson shows how to turn these ideas into copyable production patterns.

Ask your teacher "Roughly how much comprehension debt am I carrying with agents today?" "Am I in cognitive surrender, and how do I self-check?" "Which part of my work is best suited to using a loop to speed up understanding rather than avoid it?" Anything unclear is fair game.

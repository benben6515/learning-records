Loop Engineering Basics Cheat Sheet

One page: paradigm, harness vs loop, six primitives, loop anatomy, L1/L2/L3, risk.

Definition in one line

Replace yourself as the person who prompts the agent. A loop = a recursive goal: you define a purpose, the agent iterates with sub-agents + external memory until done or handed back to you. You design it once; you don't prompt the steps.

Harness vs Loop (don't confuse them)

HarnessLoop

Makeuptools / context / permissions / rulesharness + scheduling + state + verification chain
SolvesMaking "this run" go wellOrchestrating runs over time

Minimal viable loop = scheduling + one triage skill + a state file; add the rest one at a time as value is proven.

Loop anatomy (one run)

The implementer never grades its own homework — the verifier is what lets you walk away.

Risk: the loop doesn't delete you

Three problems that get amplified Intent debt: every cold start fills gaps with confident guesses → pay it down with skills.
Comprehension debt: faster shipping, less you understand → read what it wrote.
Cognitive surrender: letting it run while you stop having opinions → design with judgment, don't use it to avoid thinking.
Orchestration tax: the human cost of parallel agents; worktrees remove mechanical collisions, you remain the ceiling.

`/goal` vs `/loop`

  • /loop = re-runs on a cadence (every N min/hours).
  • /goal = runs until a verifiable condition holds, with a different model checking "done" (maker/checker applied to the stop condition).

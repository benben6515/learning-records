第 03 課 · 路由

不用框架做路由

第 01 課的路由是 if 陳述式。今天它們長成一張真正的路由表——路徑參數、內文解析、驗證、錯誤防護網——你也將拿到第一個真正的 REST 端點。

約 35 分鐘 動手做 Node.js

為什麼是這一課

你用過 Express 的路由，但你從未擁有過一個。這一課用約 55 行的純 Node 蓋出完整機制——配對、抽取、驗證、失敗。之後 Express 對你不再是盲目信任的依賴：它是你有能力自己寫的庫（只是更整潔的版本）。這也是第 05 課接上資料庫時要用的骨架。

核心觀念

路由＝把請求配對到 handler，並抽出它的輸入。配對是「方法＋路徑」對照一張表；輸入只存在四個地方——學一次，每個框架都一樣（Express 路由指南）：

輸入長相住在哪
路徑參數/notes/42在路徑裡——由樣板 /notes/:id 擷取
查詢字串?page=2&limit=10url.searchParams（第 02 課見過）
內文{"title":"buy milk"}一個串流——先重組，再 JSON.parse（第 01 課）
標頭authorization: Bearer …req.headers 物件

程式碼——完整的 notes API，不用框架

存成 server3.mjs。這是課程到目前最長的一份程式碼——但每個零件你都已經見過了：

import { createServer } from "node:http";

// ——— 資料（先放記憶體；持久化是第 05 課）———
const notes = new Map();
let nextId = 1;

// ——— 輔助函式 ———
function readBody(req) {                 // 重組內文串流（第 01 課）
  return new Promise((resolve) => {
    let body = "";
    req.on("data", (c) => (body += c));
    req.on("end", () => resolve(body));
  });
}

function json(res, status, data) {       // 狀態＋標頭＋內文，一次搞定
  res.writeHead(status, { "content-type": "application/json" });
  res.end(data === undefined ? "" : JSON.stringify(data));
}

// ——— 路由表：方法＋樣板 → handler ———
const routes = [
  { method: "GET", pattern: "/notes", handler: (req, res) =>
      json(res, 200, [...notes.values()]) },

  { method: "POST", pattern: "/notes", handler: async (req, res) => {
      const note = JSON.parse((await readBody(req)) || "{}");
      if (!note.title) return json(res, 400, { error: "title is required" });
      note.id = nextId++;
      notes.set(note.id, note);
      json(res, 201, note);
  } },

  { method: "GET", pattern: "/notes/:id", handler: (req, res, p) => {
      const note = notes.get(Number(p.id));
      if (!note) return json(res, 404, { error: "note not found" });
      json(res, 200, note);
  } },

  { method: "DELETE", pattern: "/notes/:id", handler: (req, res, p) => {
      if (!notes.delete(Number(p.id))) return json(res, 404, { error: "note not found" });
      json(res, 204);
  } },
];

// "/notes/:id" → /^\/notes\/(?<id>\d+)\/?$/
const toRegex = (pattern) =>
  new RegExp("^" + pattern.replace(/:(\w+)/g, "(?<$1>\\d+)") + "/?$");

// ——— 分派：第一個配對到的路由獲勝；try/catch 是錯誤防護網 ———
const server = createServer(async (req, res) => {
  const { pathname } = new URL(req.url, "http://localhost");
  console.log(`${req.method} ${pathname}`);
  try {
    for (const route of routes) {
      if (req.method !== route.method) continue;
      const match = pathname.match(toRegex(route.pattern));
      if (match) return await route.handler(req, res, match.groups ?? {});
    }
    json(res, 404, { error: "not found" });
  } catch (err) {                       // Express 會替你裝好這個
    console.error(err);
    json(res, 500, { error: "internal error" });
  }
});

server.listen(3000, () => console.log("listening on http://localhost:3000"));

三個值得注意的地方

  • 路由表就是資料。一個可以 loop、filter、擴充的陣列——路由器的全部就是這樣。（Express 的 app.get() 也是把東西推進一張很像的清單。）
  • :id 編譯成具名擷取群組。match.groups 交給 handler { id: "42" }——我們手做的 req.params。注意 Number(...)：URL 而來的一切都是字串。
  • try/catch 是錯誤防護網——而 await 是絆線。return await route.handler(…) 才能把 reject 的 promise 引進 catch。只寫 return route.handler(…)，rejection 會繞過 try、500 永遠不會發生、程序直接死掉。（沒錯——我驗證這課程式碼時就親自踩到這個 bug。）刪掉 catch、送出畸形 JSON，親眼看看；接住、記 log、回 500，是你剛剛實作的框架功能（Node http 文件 · Express 路由）。

實戰練習——curl 打完整 CRUD

動手做 · 建立、讀取、驗證、弄壞、刪除
  • 存成 server3.mjs，啟動：node server3.mjs
  • 列清單（空的）：curl -i http://localhost:3000/notes → 200，[]
  • 建立：curl -i -X POST -H "content-type: application/json" -d '{"title":"buy milk"}' http://localhost:3000/notes → 201 帶 id
  • 讀單筆：curl -i http://localhost:3000/notes/1 → 200；再打 /notes/99 → 你寫的 404
  • 驗證：curl -i -X POST -d '{}' http://localhost:3000/notes → 400 "title is required"
  • 弄壞它：curl -i -X POST -d '{oops' http://localhost:3000/notes → 500，server log 裡有一整份 stack trace——防護網接住了
  • 刪除：curl -i -X DELETE http://localhost:3000/notes/1 → 204（無內文）；再 GET 一次 → 404
  • 對照：為每個 Express 零件找到我們的那一行——app.get()、req.params、express.json()、res.json()、預設錯誤處理器

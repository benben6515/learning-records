第 08 課 · 測試

測試 API：紅、綠、重構

你的 server7 帶著兩個真 bug 通過了你我兩人的眼睛——getSid 裡一個字元的漂移，以及重構時弄丟了讀取端點所有權檢查。curl 練習從沒發現，因為練習只檢查你記得試的東西。今天：node --test、零新依賴，以及正好宰掉這兩個 bug 的測試。

約 40 分鐘 動手做 品質

為什麼是這一課

第 01–07 課沒有任何東西會自我驗證。你跑 curl、看到 200、感覺良好——然後兩個 bug 揚長而過：startsWith("sid") 而不是 startsWith("sid=")（你上一課找到了），還有 getNoteById 對一個陌生人讀你的筆記回 200——因為重構進 utils/ 時防線掉了。我發現它們只是因為我讀了你的程式碼。測試，就是讓程式碼在每次變更時都被重新讀一遍——由一台永遠不會累的機器。

核心觀念

測試＝一個用選定輸入執行你的程式碼、然後斷言輸出的函式——寫來在行為漂移的那一刻大聲失敗。 圍繞它的習慣有三個拍子（Fowler：TDD）：先寫測試、親眼看它失敗（紅——必須先失敗，否則它什麼都沒測），用最誠實的簡單方式讓它通過（綠），然後在測試的看守下收拾乾淨（重構）。

步驟一——誘餌測試宰掉單字元 bug

首先，可測性：getSid 搬進 utils/index.mjs 並加上 export。然後是測試——注意它的形狀：安排（arrange）、行動（act）、斷言（assert），一個行為，一個讀起來像句子的名稱：

// utils/get-sid.test.mjs
import test from "node:test";
import assert from "node:assert/strict";
import { getSid } from "./index.mjs";

test("returns the sid when a decoy cookie merely starts with sid", () => {
  const req = { headers: { cookie: "sidebar=hide; sid=the-real-one" } };   // 安排
  assert.equal(getSid(req), "the-real-one");                               // 行動＋斷言
});

test("returns undefined when no cookie header exists", () => {
  assert.equal(getSid({ headers: {} }), undefined);
});

對著帶 bug 的版本跑——失敗就是這一課，仔細看：

$ node --test utils/get-sid.test.mjs
✖ returns the sid when a decoy cookie merely starts with sid
    AssertionError: Expected values to be strictly equal:
    + actual: 'bar=hide'          // ← 誘餌 cookie 被切了一半
    expected: 'the-real-one'

sidebar=hide 以 sid 開頭，所以 .find() 抓走它、slice(4) 回傳 bar=hide 當你的 session id。修掉那一個字元——startsWith("sid=")——suite 轉綠。你早就知道這個 bug；現在它回不來了：未來任何讓這四個字元漂移的編輯，都會在 40 毫秒內把整個 build 染紅。

步驟二——可測性是設計屬性

你手打的那些 curl？它們就是測試——慢、手動、健忘。伺服器只需要一個配合：不要在 import 時就 listen，改成 export 一個 start：

// server7.mjs 最底部 —— 原本是：app.listen(3322, …)
export function start(port = 3322) {
  return new Promise((resolve) => app.listen(port, () => resolve(app)));
}

start(0) 跟 OS 要一個臨時埠——測試可並行，永遠不用跟你的 dev server 搶 3000/3322。

步驟三——整合測試：整份合約，走真 HTTP

Node 有全域 fetch 和 node --test——不用 supertest、不用 jest、什麼都不用裝（node:test 文件）。這一個檔案同時釘住 L04 與 L07 的承諾：

// api.test.mjs — 整合測試：真 HTTP、真 Postgres、真合約
import test from "node:test";
import assert from "node:assert/strict";
import { start } from "./server7.mjs";

let app, base;
const api = (path, opts = {}) => fetch(base + path, opts);
const post = (path, body, cookie) => api(path, {
  method: "POST",
  headers: { "content-type": "application/json", ...(cookie ? { cookie } : {}) },
  body: JSON.stringify(body),
});

test("the notes contract, through real HTTP", async () => {
  app = await start(0);                                 // 臨時埠
  base = `http://localhost:${app.address().port}`;
  const mail = `t${Date.now()}@x.dev`;                  // 每次跑都唯一——不需要清理 fixture

  assert.equal((await post("/auth/register", { email: mail, password: "correct horse" })).status, 201);
  assert.equal((await post("/auth/register", { email: mail, password: "x" })).status, 409);

  const wrong = await post("/auth/login", { email: mail, password: "WRONG" });
  const ghost = await post("/auth/login", { email: "ghost@x.dev", password: "WRONG" });
  assert.equal(wrong.status, 401);
  assert.equal(await wrong.text(), await ghost.text());          // 相同回應本體——不可列舉

  const ok = await post("/auth/login", { email: mail, password: "correct horse" });
  assert.equal(ok.status, 200);
  const cookie = ok.headers.getSetCookie()[0].split(";")[0];     // "sid=…"

  const created = await post("/notes", { title: "from a test" }, cookie);
  assert.equal(created.status, 201);
  assert.ok(created.headers.get("location"));

  // 一個完全登入的陌生人，要求那筆筆記 →
  const stranger = await post("/auth/register", { email: `s${Date.now()}@x.dev`, password: "p" });
  const sLogin = await post("/auth/login", { email: (await stranger.json()).email, password: "p" });
  const sCookie = sLogin.headers.getSetCookie()[0].split(";")[0];
  assert.equal((await api(`/notes/${(await created.json()).id}`, { headers: { cookie: sCookie } })).status, 403);

  assert.equal((await post("/auth/logout", {}, cookie)).status, 204);
  assert.equal((await api("/auth/me", { headers: { cookie } })).status, 401);
});

test.after(() => app?.close());

我對著你的 server7 跑的時候，發生了什麼

200 !== 403。陌生人讀到了筆記。你重構進 utils/ 時，不知不覺把 getUser 和所有權檢查從 getNoteById 弄丟了——任何人、甚至沒登入，都能用 id 讀任何筆記。這是一個 IDOR 漏洞（Insecure Direct Object Reference，不安全的直接物件參照），正是第 07 課警告過的「少一條 WHERE」家族，住在一個 curl 全回 200 的程式碼裡。修法就是你已經認得的防線：

async function getNoteById(req, res, p) {
  const me = await getUser(req);
  if (!me) return fail(res, 401, "UNAUTHENTICATED", "log in first");
  const note = await q.get(Number(p.id));
  if (!note) return fail(res, 404, "NOT_FOUND", "note not found");
  if (note.user_id !== me.id) return fail(res, 403, "FORBIDDEN", "not your note");
  return json(res, 200, note);
}

……然後 suite 變成 pass 4, fail 0。順便檢查你自己的 getNotes 列清單 handler——同一場重構、同一種風險。

四個值得注意的地方

  • 先紅，否則它什麼都沒測。我修好 getSid 後又故意弄壞它（變異測試 mutation check），看著誘餌測試再次變紅——證明測試有牙。一個從沒失敗過的測試，是一個從沒工作過的測試。
  • 單元 vs 整合是縮放層級。誘餌測試在毫秒內釘住一個函式；API 測試在約 600 毫秒內釘住整份合約（驗證、cookie、狀態碼、所有權）。兩個都要：API 測試抓到單元測試看不到的 403 洞；單元測試在壞掉時指名道姓到那一行（Fowler：測試金字塔）。
  • 測試是會執行的文件。新同事讀 get-sid.test.mjs 就確切知道 getSid 承諾什麼——誘餌 cookie 也算——不必打開你的腦袋。
  • 每個 bug 都變成一個測試。今天的兩個 bug 從此被永久圍欄。這是長期賽局：你的 suite 是一份「這份程式碼曾經錯過的所有方式」清單，每一條上面都裝了絆線。

實戰練習——為你自己的程式碼圍欄

動手做 · 紅、綠，與變異遊戲
  • 把 getSid 搬進 utils/index.mjs 加 export；寫 get-sid.test.mjs 含誘餌測試；跑 node --test utils/get-sid.test.mjs——如果你的 bug 還在，品嚐那個紅，然後修好轉綠
  • 給 server7 加 export function start(port)（取代裸的 app.listen）；在底部用一次 start(3322) 確認平常的啟動方式照舊
  • 照 listing 寫 api.test.mjs；跑整個 suite：node --test——如果你的 handler 還沒補防線，預期陌生人測試以 200 !== 403 失敗
  • 修好讀取路徑（防線＋所有權，如上）；用同樣的「防線掉落病」標準審查 getNotes／postNote／deleteNoteById；suite 到 fail 0
  • 變異遊戲：故意弄壞一個東西（刪掉 403 那行、或把 sid= 改回去）→ 看著確切那個測試變紅 → 還原。感受安全網接住什麼
  • 把欄杆加長：為 PUT 冪等性（第二個一模一樣的 PUT → 200）、錯動詞 405＋Allow、壞 JSON → 400、清單劃界（陌生人的清單是 []）補上測試
  • 變成習慣：在 package.json scripts 加 "test": "node --test"；從今以後，任何變更的迴圈都是紅 → 綠 → 重構

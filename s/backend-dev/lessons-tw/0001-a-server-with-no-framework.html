第 01 課 · node:http

不用框架寫伺服器

你已經呼叫過 fetch() 上千次了。今天，你來建造回答它的那一方——不用任何框架，也沒有任何你看不見的東西。

約 30 分鐘 動手做 Node.js

為什麼是這一課

你的任務宣言寫著：沒有任何一層是魔法。在 Express、Next API routes、資料庫之前——先有一個平凡的 Node 程序，收到位元組、寫出位元組。你未來用到的每個框架，都只是包裝你現在要親手寫的這個東西。寫過一次之後，req 與 res 就再也不是咒語了。

核心觀念

Web 伺服器就是一個每個請求都會被呼叫的函式。它收到一個請求物件，然後對一個回應物件寫入。工作內容就這麼多。

用戶端 (fetch, curl)  ─ 請求 ─▶ 你的函式 (req, res)  ─ 回應 ─▶ 用戶端

HTTP 請求（request）是：一個方法（method）＋路徑（path）（合稱「起始行」）、標頭（headers）（詮釋資料）、以及可省略的內文（body）。回應（response）是：一個狀態碼（status code）、標頭、以及可省略的內文。Node 把請求交給你成為 req，把「即將送出的回應」交給你成為 res（Node http 文件；MDN：HTTP 訊息）。

狀態碼：五大家族

狀態碼是你與用戶端之間合約的那一半——在用戶端解析內文之前，伺服器就用它說明了發生什麼事（MDN：HTTP 回應狀態碼）。

家族意義你會用到
1xx資訊—（少見，低層自動處理）
2xx成功200 OK、201 Created、204 No content
3xx重新導向301 搬家了、304 沒變
4xx用戶端出錯400、401、403、404、429
5xx伺服器出錯500、502、503

程式碼——約 25 行，每個 import 你都看得懂

存成 server.mjs（.mjs 副檔名告訴 Node 使用現代 ES modules，不需要任何設定）：

import { createServer } from "node:http";

const server = createServer((req, res) => {
  const { method, url } = req;
  console.log(`${method} ${url}`);        // 每個請求都會在這裡留下紀錄

  // GET / — 純 JSON 的 hello
  if (method === "GET" && url === "/") {
    res.writeHead(200, { "content-type": "application/json" });
    res.end(JSON.stringify({ hello: "server" }));
    return;
  }

  // POST /echo — 先讀請求內文，再回話
  if (method === "POST" && url === "/echo") {
    let body = "";
    req.on("data", (chunk) => (body += chunk));   // 內文是一塊一塊抵達的
    req.on("end", () => {
      res.writeHead(201, { "content-type": "application/json" });
      res.end(JSON.stringify({ youSent: body }));
    });
    return;
  }

  // 其他路徑 — 是我們「決定」要回 404。沒有任何自動行為。
  res.writeHead(404, { "content-type": "application/json" });
  res.end(JSON.stringify({ error: "not found" }));
});

server.listen(3000, () => console.log("listening on http://localhost:3000"));

執行之前，有三件事值得注意：

  • 路由就只是 if 陳述式。方法＋路徑進來，決策出去。路由的全部就是這樣。
  • 請求內文是一個串流（stream）。它分批以 data 事件抵達，你再把它組回來——HTTP 不保證內文「一次到齊」（IncomingMessage 是一個 readable stream）。
  • 沒有任何人替你回答。忘記 res.end()，請求就懸在那裡。那個 404 會存在，只因為你親手寫了它。

實戰練習——跑起來，讀懂線上的原始訊息

動手做 · 回饋迴路就是你的終端機

每一步都會產生看得見的輸出——如果看到的和預期不符，停下來看：那個落差就是學習本身。

  • 建一個資料夾 hello-server，把上面的程式碼存成 server.mjs
  • 啟動：node server.mjs——看到它印出 listening on http://localhost:3000
  • 開第二個終端機：curl http://localhost:3000/——應該收到 {"hello":"server"}
  • 張開眼睛看：curl -i http://localhost:3000/——狀態行、標頭、空行、內文
  • 送內文：curl -i -X POST -d "ping" http://localhost:3000/echo——預期 201 與回聲
  • 弄壞它：curl -i http://localhost:3000/nope——預期你自己寫的 404
  • 對照：把 curl -i 輸出的每一部分，對應到 server.mjs 裡產生它的那一行

最後這個 curl 應該長這樣——在程式碼裡找出每一行的出處：

$ curl -i http://localhost:3000/
HTTP/1.1 200 OK
content-type: application/json
Date: Tue, 25 Aug 2026 09:12:41 GMT
Connection: keep-alive
Keep-Alive: timeout=5
Transfer-Encoding: chunked
                                          ← 空行：標頭結束、內文開始
{"hello":"server"}
你剛剛證明了什麼

Express 的 app.get("/", handler) 只是一個比較漂亮的 if。它的 res.json() 就是 writeHead ＋ end(JSON.stringify(...))。它的 express.json() 中介軟體（middleware），就是你在 /echo 裡寫的「收集資料塊」。你已經親自擁有過每一個零件——框架往後只會重新整理你已經理解的東西。

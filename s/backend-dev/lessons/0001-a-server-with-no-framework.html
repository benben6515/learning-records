Lesson 01 · node:http

A Server With No Framework

You have called fetch() thousands of times. Today you build the thing that answers — with zero frameworks, and nothing you cannot see.

~30 min hands-on Node.js

Why this lesson

Your mission says: no layer is magic. Before Express, before Next API routes, before databases — there is a plain Node process that receives bytes and writes bytes. Every framework you'll ever use is a wrapper around what you're about to write by hand. Once you've done this, req and res stop being incantations.

The one idea

A web server is one function that gets called for every request. It receives a request object, and writes to a response object. That's the whole job.

client (fetch, curl)  ─ request ─▶ your function (req, res)  ─ response ─▶ client

An HTTP request is: a method + path (the "start line"), headers (metadata), and an optional body. A response is: a status code, headers, and an optional body. Node hands you the request as req and the response-to-be as res (Node http docs; MDN: HTTP messages).

Status codes: the five families

The status code is your half of the contract with the client — it's how the server says what happened before the client parses the body (MDN: HTTP response status codes).

FamilyMeansYou'll use
1xxinformational— (rare, handled low-level)
2xxsuccess200 OK, 201 Created, 204 No content
3xxredirection301 Moved, 304 Not modified
4xxthe client messed up400, 401, 403, 404, 429
5xxthe server messed up500, 502, 503

The code — ~25 lines, no imports you can't read

Save this as server.mjs (the .mjs extension tells Node to use modern ES modules, no config needed):

import { createServer } from "node:http";

const server = createServer((req, res) => {
  const { method, url } = req;
  console.log(`${method} ${url}`);        // every request logs here

  // GET / — plain JSON hello
  if (method === "GET" && url === "/") {
    res.writeHead(200, { "content-type": "application/json" });
    res.end(JSON.stringify({ hello: "server" }));
    return;
  }

  // POST /echo — read the request body, then answer
  if (method === "POST" && url === "/echo") {
    let body = "";
    req.on("data", (chunk) => (body += chunk));   // body arrives in chunks
    req.on("end", () => {
      res.writeHead(201, { "content-type": "application/json" });
      res.end(JSON.stringify({ youSent: body }));
    });
    return;
  }

  // anything else — we decide it's a 404. Nothing automatic.
  res.writeHead(404, { "content-type": "application/json" });
  res.end(JSON.stringify({ error: "not found" }));
});

server.listen(3000, () => console.log("listening on http://localhost:3000"));

Three things worth noticing before you run it:

  • Routing is just if statements. Method + path in, decision out. That's all routing is.
  • The request body is a stream. It arrives in data chunks and you reassemble it — nothing in HTTP guarantees it arrived "at once" (IncomingMessage is a readable stream).
  • Nothing answers for you. Forget res.end() and the request hangs. The 404 exists only because you wrote it.

The drill — run it and read the wire

Hands-on · the feedback loop is your terminal

Each step produces visible output — if what you see doesn't match, stop and look: that gap is the learning.

  • Create a folder hello-server, save the code above as server.mjs
  • Start it: node server.mjs — watch it log listening on http://localhost:3000
  • In a second terminal: curl http://localhost:3000/ — you should get {"hello":"server"}
  • Now with eyes: curl -i http://localhost:3000/ — status line, headers, blank line, body
  • Send a body: curl -i -X POST -d "ping" http://localhost:3000/echo — expect 201 and the echo
  • Break it: curl -i http://localhost:3000/nope — expect your 404
  • Map it: for each part of the curl -i output, find the exact line in server.mjs that produced it

The last curl should look like this — find each line's source in your code:

$ curl -i http://localhost:3000/

What you just proved

Express's app.get("/", handler) is a prettier if. Its res.json() is writeHead + end(JSON.stringify(...)). Its express.json() middleware is the chunk-collecting you wrote in /echo. You have now personally owned every piece — the framework will only ever organise what you already understand.

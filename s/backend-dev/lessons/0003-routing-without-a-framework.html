Lesson 03 · Routing

Routing Without a Framework

Lesson 01's routing was if statements. Today those grow into a real route table — path params, body parsing, validation, and an error net — and you earn your first true REST endpoint.

~35 min hands-on Node.js

Why this lesson

You've used Express routes; you've never owned one. This lesson builds the full mechanism — matching, extracting, validating, failing — in ~55 lines of raw Node. After this, Express is not a dependency you trust blindly: it's a library you could have written (a tidier version of it, anyway). This is also the skeleton Lesson 05 will attach a database to.

The one idea

Routing = matching a request to a handler, and extracting its inputs. The match is method + path against a table. The inputs live in exactly four places — learn them once, they're the same in every framework (Express routing guide):

The code — a complete notes API, no framework

Save as server3.mjs. It's the longest listing of the course so far — but every piece is something you already met:

import { createServer } from "node:http";

// ——— the data (in-memory for now; persistence is Lesson 05) ———
const notes = new Map();
let nextId = 1;

// ——— helpers ———
function readBody(req) {                 // reassembles the body stream (Lesson 01)
  return new Promise((resolve) => {
    let body = "";
    req.on("data", (c) => (body += c));
    req.on("end", () => resolve(body));
  });
}

function json(res, status, data) {       // status + headers + body, one call
  res.writeHead(status, { "content-type": "application/json" });
  res.end(data === undefined ? "" : JSON.stringify(data));
}

// ——— the route table: method + pattern → handler ———
const routes = [
  { method: "GET", pattern: "/notes", handler: (req, res) =>
      json(res, 200, [...notes.values()]) },

  { method: "POST", pattern: "/notes", handler: async (req, res) => {
      const note = JSON.parse((await readBody(req)) || "{}");
      if (!note.title) return json(res, 400, { error: "title is required" });
      note.id = nextId++;
      notes.set(note.id, note);
      json(res, 201, note);
  } },

  { method: "GET", pattern: "/notes/:id", handler: (req, res, p) => {
      const note = notes.get(Number(p.id));
      if (!note) return json(res, 404, { error: "note not found" });
      json(res, 200, note);
  } },

  { method: "DELETE", pattern: "/notes/:id", handler: (req, res, p) => {
      if (!notes.delete(Number(p.id))) return json(res, 404, { error: "note not found" });
      json(res, 204);
  } },
];

// "/notes/:id" → /^\/notes\/(?<id>\d+)\/?$/
const toRegex = (pattern) =>
  new RegExp("^" + pattern.replace(/:(\w+)/g, "(?<$1>\\d+)") + "/?$");

// ——— dispatch: first matching route wins; the try/catch is the error net ———
const server = createServer(async (req, res) => {
  const { pathname } = new URL(req.url, "http://localhost");
  console.log(`${req.method} ${pathname}`);
  try {
    for (const route of routes) {
      if (req.method !== route.method) continue;
      const match = pathname.match(toRegex(route.pattern));
      if (match) return await route.handler(req, res, match.groups ?? {});
    }
    json(res, 404, { error: "not found" });
  } catch (err) {                       // Express installs one of these for you
    console.error(err);
    json(res, 500, { error: "internal error" });
  }
});

server.listen(3000, () => console.log("listening on http://localhost:3000"));

Three things to notice

  • The route table is data. An array you can loop, filter, extend — that's all a router is. (Express's app.get() pushes into a list not unlike this one.)
  • :id compiles to a named capture group. match.groups hands the handler { id: "42" } — our hand-rolled req.params. Note the Number(...): everything from the URL arrives as a string.
  • The try/catch is the error net — and the await is the tripwire. return await route.handler(…) routes a rejected promise into the catch. Write plain return route.handler(…) and the rejection slips past the try, the 500 never happens, and the process dies. (Yes — I hit exactly that bug verifying this lesson's code.) Delete the catch, send malformed JSON, and watch it happen; catching, logging, and answering 500 is a framework feature you just implemented (Node http docs · Express routing).

The drill — full CRUD on curl

Hands-on · create, read, validate, break, delete
  • Save as server3.mjs, start it: node server3.mjs
  • List (empty): curl -i http://localhost:3000/notes → 200, []
  • Create: curl -i -X POST -H "content-type: application/json" -d '{"title":"buy milk"}' http://localhost:3000/notes → 201 with an id
  • Read one: curl -i http://localhost:3000/notes/1 → 200; then /notes/99 → your 404
  • Validation: curl -i -X POST -d '{}' http://localhost:3000/notes → 400 "title is required"
  • Break it: curl -i -X POST -d '{oops' http://localhost:3000/notes → 500, and a stack trace in the server log — the error net caught it
  • Delete: curl -i -X DELETE http://localhost:3000/notes/1 → 204 (no body); GET it again → 404
  • Map it: find our line for each Express piece — app.get(), req.params, express.json(), res.json(), the default error handler

PostgreSQL 急救包

第 06 課濃縮一張卡：容器指令、連線字串、30 行 migration runner、$n 參數、值得背的錯誤碼、以及看見一切的 psql 指令——整理自 node-postgres 文件與 postgresql.org。列我。

啟動／停止／炸掉「另一台機器」

$ docker run -d --name bd-pg -e POSTGRES_PASSWORD=dev -e POSTGRES_DB=notes -p 5432:5432 postgres:17-alpine
$ docker start bd-pg                  // 重開機／暫停之後
$ docker exec bd-pg pg_isready -U postgres
$ docker rm -f bd-pg                  // 炸掉——migration 會重建一切
$ export DATABASE_URL="postgres://postgres:dev@localhost:5432/notes"
//        帳號 ─┘└密碼┘ └主機┘└埠┘└資料庫

Migration 模式（任何工具，同樣骨架）

migrations/
  0001_init.sql          // 有編號、有順序、只跑一次——已套用的檔案永遠不改
  0002_add_done.sql
  0003_add_priority.sql

// runner 蒸餾版：
帳本    = CREATE TABLE IF NOT EXISTS schema_migrations (name TEXT PRIMARY KEY, …)
已套用  = SELECT name FROM schema_migrations
for 檔案 of 排序(migrations/*.sql) 不在 已套用:
    BEGIN; 執行(檔案); INSERT INTO schema_migrations; COMMIT   // 不然就 ROLLBACK

從 Node 查詢（pg）

import pg from "pg";
const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL });

const rows = (await pool.query("SELECT * FROM notes WHERE id = $1", [7])).rows;
const n    = (await pool.query("DELETE FROM notes WHERE id = $1", [7])).rowCount;
// $1、$2 … 有編號的參數——跟 SQLite 的 ? 同一條反 injection 規則
// rows[]＝SQLite 的 .all()；rowCount＝.changes()；rows[0]＝.get()

值得背的錯誤碼

碼名稱映射到
23505unique_violation409——那個使用者名稱／email 已存在
23514check_violation400——值被 CHECK 約束拒絕
23503foreign_key_violation400/409——參考到不存在的列
23502not_null_violation400——你的 handler 早該先擋下
42P01undefined_table500＋去跑你的 migration！

完整清單：錯誤碼附錄。模式：在 handler 接 err.code、翻譯進錯誤合約，其他一律 re-throw 給防護網。

用 psql 親眼看

$ docker exec -it bd-pg psql -U postgres -d notes
notes=# \d notes                       // 表的形狀：欄位、型別、約束
notes=# \dt                            // 所有表（含 schema_migrations）
notes=# SELECT id, title FROM notes;
notes=# \q
// 一次性：
$ docker exec bd-pg psql -U postgres -d notes -c "SELECT * FROM schema_migrations;"

現在就值得知道的坑

  • Pool ≠ Client。Pool 為長壽的伺服器保溫連線；Client 是腳本用的單一連線（我們的 migrate.mjs 用 pool.connect() 借一條，讓 BEGIN/COMMIT 留在同一條連線上）。
  • Identity id 唯一、但不連續。失敗的插入照樣燒序號——我實測跑出 1, 4, 7。永遠別把邏輯蓋在「連續」上。
  • ECONNREFUSED ::1 排在 127.0.0.1 前面是 Node 先試 IPv6。解法是「把資料庫開起來」，不是換 host 字串。
  • 日期用 TIMESTAMPTZ——帶時區的時刻，序列化成 ISO（2026-09-08T03:30:22.111Z）。存時刻，時區留到邊界再呈現。

SQLite 急救包

第 05 課的全部壓縮成一张卡：Node 內建模組、CRUD 資料層的五個語句、殺死 SQL injection 的 ? 規則、以及親眼看見資料的 CLI 指令——整理自 node:sqlite 文件與 sqlite3 CLI 文件。列我。

三行起步

import { DatabaseSync } from "node:sqlite";        // Node 23+（22.5+ 加 --experimental-sqlite）

const db = new DatabaseSync("notes.db");           // 整個資料庫就是這個檔案
db.exec(`CREATE TABLE IF NOT EXISTS notes (
  id INTEGER PRIMARY KEY, title TEXT NOT NULL,
  created_at TEXT DEFAULT (datetime('now'))
)`);

CRUD 資料層的五個語句

const q = {
  list:   db.prepare("SELECT id, title FROM notes ORDER BY id"),
  get:    db.prepare("SELECT id, title FROM notes WHERE id = ?"),
  insert: db.prepare("INSERT INTO notes (title) VALUES (?) RETURNING id, title"),
  upsert: db.prepare(`INSERT INTO notes (id, title) VALUES (?, ?)
            ON CONFLICT(id) DO UPDATE SET title = excluded.title
            RETURNING id, title`),                // 冪等 PUT（L04）濃縮成一個子句
  del:    db.prepare("DELETE FROM notes WHERE id = ?"),
};

q.list.all()          // → 列物件陣列
q.get.get(7)          // → 第一列物件 | undefined
q.insert.get("milk")  // → RETURNING 那列（id 由 SQLite 鑄造）
q.del.run(7).changes  // → 影響的列數（0 ⇒ 你的 404）

保命規則

規則原因
? 參數，永遠不用模板字串資料進不了 SQL 本文 ⇒ injection 淪為一則蠢標題。接字串（\`…'${title}'\`）就會執行它。
INTEGER PRIMARY KEY＝自動 idSQLite 的 rowid 負責發號——取代 nextId++，不會相撞。
NOT NULL＋DEFAULT 寫進 schema你 400 驗證的 DB 等級分身——壞列根本無法存在，不管 bug 在哪。
預備一次（模組層級），永遠執行解析/規劃一次；每次只帶參數。一個 q 物件＝完整的資料存取層。
.changes === 0 ⇒ 404DELETE/UPDATE 會回報影響列數——零表示 id 不存在。

用 sqlite3 CLI 親眼看

$ sqlite3 notes.db ".schema"              # 合約本體，直接從檔案讀出
$ sqlite3 notes.db ".tables"
$ sqlite3 notes.db "SELECT id, title FROM notes WHERE title LIKE '%milk%'"
$ sqlite3 notes.db -box "SELECT * FROM notes"   # 美美表格
$ ls -la notes.db notes.db-wal                # DB 是檔案；-wal 是它的日誌

現在就值得知道的坑

  • DatabaseSync 是同步的——故意的。每個語句都佔住事件迴圈（第 02 課！）。本機/單人使用沒問題；這是真正的網路資料庫（PostgreSQL，下一課）走非同步連線的原因之一。
  • 參數看順序。第二個 ? 綁第二個引數——順序錯不會報錯，只會資料怪怪的。
  • SQLite 型別很寬鬆。TEXT/INTEGER/NULL/REAL/BLOB，欄位是動態型別。PostgreSQL（下一課）像 TypeScript 一樣強制型別——做好心理準備。
  • 同時只有一個寫入者。讀可以很多、寫只有一個——需要多機器並發寫入的那一刻，就是 PostgreSQL 上場的時候。

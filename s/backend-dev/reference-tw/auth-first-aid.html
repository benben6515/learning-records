驗證急救包

第 07 課濃縮一張卡：scrypt 輔助函式、session 表、cookie 旗標與各自抵擋的攻擊、401/403 合約、sessions vs tokens 抉擇——整理自 OWASP cheat sheets、node:crypto與 MDN。列我。

密碼儲存（node:crypto，零依賴）

import { randomBytes, scrypt as _scrypt, timingSafeEqual } from "node:crypto";
import { promisify } from "node:util";
const scrypt = promisify(_scrypt);

async function hashPassword(password) {           // 註冊
  const salt = randomBytes(16).toString("hex");
  const hash = (await scrypt(password, salt, 64)).toString("hex");
  return `${salt}:${hash}`;
}
async function verifyPassword(password, stored) { // 登入
  const [salt, hash] = stored.split(":");
  const test = await scrypt(password, salt, 64);
  return timingSafeEqual(Buffer.from(hash, "hex"), test);
}

雜湊 ≠ 加密（沒有「解」）。刻意慢（暴力窮舉的經濟學）。每人獨特的鹽（彩虹表死）。timingSafeEqual（時間攻擊）。用非同步版——同步會阻塞迴圈。

Session 機械

登入:   sid = randomBytes(32).toString("hex")     // 256 位元——「猜不到」就是職責
         INSERT INTO sessions (sid, user_id) …
         Set-Cookie: sid=…; HttpOnly; SameSite=Lax; Path=/; Max-Age=604800
請求:   SELECT u.id, u.email FROM sessions s JOIN users u …
         WHERE s.sid = $1 AND s.expires_at > now()
登出:   DELETE FROM sessions WHERE sid = $1  （＋Max-Age=0 的 cookie）

Cookie 旗標——哪面盾擋哪種攻擊

旗標抵擋原理
HttpOnlyXSS 偷 sidJS 被禁止讀取 cookie
SameSite=LaxCSRF（跨站發送）瀏覽器不跨站附帶
Secure網路竊聽限 HTTPS——正式環境加上
Max-Age永生 sessioncookie 壽命；真正的裁判是 DB 的 expires_at

401 / 403 合約

401 UNAUTHENTICATED403 FORBIDDEN
意思「我不認識你」「認識你——但不行」
客戶端該去登入／換憑證放棄；重試沒有用

登入失敗：錯密碼和不存在 email 回同一個 401——不給列舉使用者。

JWT 是簽名的，不是加密的——echo 中段 | base64 -d 就是證明。簽章＝防篡改，不是保密。

現在就值得知道的坑

  • 永不儲存、記 log、或寄送密碼。欄名叫 password_hash；用 verifyPassword 驗證，句點。
  • 授權是一條 WHERE。列清單：WHERE user_id = $1。讀單筆：先查再比主人。大多數 IDOR CVE 就是少了其中一個。
  • DB 約束當你的後盾。UNIQUE email → 23505 → 409。OWASP 規則、引擎強制。
  • 3000 埠可能被佔（我驗證到一半就被一台 Vite dev server 佔過）。EADDRINUSE 不是 bug——是作業系統誠實；換個埠。

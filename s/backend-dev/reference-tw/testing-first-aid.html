測試急救包

第 08 課濃縮一張卡：node:test 要點、AAA 形狀、可以永遠複用的整合測試骨架、紅綠規則、先測什麼——整理自 node:test與 node:assert文件，加上 Fowler 的 TDD。列我。

執行器（零安裝）

$ node --test                        // 遞迴跑所有 *.test.mjs
$ node --test utils/get-sid.test.mjs  // 單一檔案
$ node --test --test-name-pattern="decoy"   // 按名稱跑一個
// package.json: "scripts": { "test": "node --test" } → npm test

測試的形狀

test("returns the sid when a decoy cookie merely starts with sid", () => {
  const req = { headers: { cookie: "sidebar=hide; sid=the-real-one" } };  // 1 安排
  const got = getSid(req);                                                // 2 行動
  assert.equal(got, "the-real-one");                                      // 3 斷言
});

一個測試一個行為。名稱＝失敗時可讀的句子：✖ returns the sid when a decoy…。斷言：assert.equal / notEqual / ok / deepEqual / throws（從 node:assert/strict import）。

整合測試骨架（永久複用）

import test from "node:test";
import assert from "node:assert/strict";
import { start } from "./server7.mjs";          // 伺服器 export start(port)，不要裸 listen

let app, base;
const api = (path, opts = {}) => fetch(base + path, opts);

test("…", async () => {
  app = await start(0);                         // 臨時埠——可並行
  base = `http://localhost:${app.address().port}`;
  const mail = `t${Date.now()}@x.dev`;          // 每次跑資料唯一——免 fixture
  const res = await api("/auth/login", { … });
  assert.equal(res.status, 200);
  const cookie = res.headers.getSetCookie()[0].split(";")[0];   // "sid=…"
});
test.after(() => app?.close());

紅綠重構規則

規則原因
每個新測試先看到失敗不會失敗的測試不能告訴你任何事（變異檢查：弄壞、見紅、還原）
紅 → 最簡單誠實的綠紅的時候不鍍金；測試定義「完成」
只在綠燈時重構suite 是你搬移程式碼時的安全網
每個 bug 變成一個測試你的 suite＝這份程式碼錯過的每種方式，每條都裝絆線
每次變更跑整套幾秒鐘；每次 commit 前 npm test，之後交給 CI

先測什麼（優先順序）

  1. 合約：每個端點的成功狀態＋形狀（201+Location、204、清單劃界）。
  2. 錯誤路徑：400 壞 JSON、401 無/壞 session、403 跨使用者、404、405＋Allow、409 重複 email。bug 住在錯誤路徑裡。
  3. 不變量：PUT 冪等（第二個 PUT → 200）、相同的 401 本體（不可列舉）、登出立即失效。
  4. 純函式（getSid 型）：便宜、快、壞掉時指名到行。

現在就值得知道的坑

  • 不要在 import 時裸 listen()——export start(port)；測試需要 start(0) 與並行。
  • 每次跑用唯一資料（Date.now() email）在這個規模勝過精心設計的 before/after 清理 fixture。
  • 單元抓字元、整合抓洞——兩個縮放層級都要；別選邊。
  • 覆蓋率是弱目標——100% 覆蓋的程式碼照樣能錯（不斷言任何事的測試也算覆蓋）。測行為，不測行數。

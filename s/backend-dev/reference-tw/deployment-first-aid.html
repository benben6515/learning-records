部署急救包

第 09 課濃縮成一張卡：設定規則、快速失敗防線、讓 API 上線的 Render 設定、健康檢查，以及全新資料庫會端給你的各種坑——依據 twelve-factor 的 Config 原則與 Render 的 Node 部署指南。把我印出來。

規則

同一個 commit 跑遍所有環境；差異由環境承載。連接埠、資料庫 URL、機密只透過 process.env 進來，在啟動時讀取。任何環境相關的東西，不進程式碼、不進 repo、不進會被 commit 的 .env。

設定起步模板（永久收藏）

// server7.mjs
const PORT = process.env.PORT ?? 3322        // 平台指派；3322 只是本地後備值

// utils/db.mjs —— 快速失敗，在任何請求有機會 500 之前
if (!process.env.DATABASE_URL) {
  console.error("DATABASE_URL is not set — refusing to start without a database")
  process.exit(1)
}
const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL })
$ node --env-file=.env server7.mjs     // 本地：Node ≥ 20.6，零依賴

Git push 到 main ＝ 部署。平台同時會設好 PORT 與 NODE_ENV=production。先建資料庫（同一個 region），再建 web service。Internal DB URL ＝ 私有網路，不用設 TLS；External 也能用，但要加 ?ssl=true。

健康檢查（深，不是淺）

async function health(_req, res) {
  try {
    await pool.query("SELECT 1")                 // 探那個少了就不能工作的依賴
    return json(res, 200, { ok: true })
  } catch {
    return fail(res, 503, "UNHEALTHY", "database unreachable")
  }
}
// routes：{ method: "GET", pattern: "/health", handler: health }

「程序活著」≠「服務能用」。這個檢查證明整條鏈：程序起來且資料庫碰得到。回 503，絕不回 500——健康檢查失敗不是 bug，是一種狀態。

驗證部署（你自己的 curl）

$ curl -i https://your-app.onrender.com/health          // 200 {"ok":true}——走真 HTTPS
$ curl -i -X POST https://your-app.onrender.com/auth/register \
    -H 'content-type: application/json' \

// app.test.mjs：base = process.env.BASE_URL ?? `http://localhost:${app.address().port}`

值得現在就知道的坑

  • 全新資料庫會照帳本原樣重播。曾經直接改在本地 DB、卻沒寫回 migration 檔的每個修正，都會在 production 重現。修檔案，重新部署——repo 是唯一事實來源，否則就沒有任何東西是。
  • 免費 Postgres 是租的：建立後 30 天到期，14 天寬限，之後刪除。重建它就是免費練習：新 URL、同一套 migrate、同一個部署。
  • 免費 web service 會休眠：沒流量約 15 分鐘後入睡；第一位訪客等約 1 分鐘（冷啟動）。健康檢查擋不掉休眠——它擋掉的是說謊。付費執行個體可移除。
  • 務必聽 process.env.PORT，否則平台的路由永遠找不到你。用 ?? 綁後備值，本地習慣才活得了。
  • 機密住在儀表板，永遠不進 repo。DATABASE_URL 外洩？輪換它（一下點擊）、更新環境變數、重新部署——程式碼零變更。
  • 崩潰會被平台的監督者重啟。在 VPS 上那是你的 systemd unit 或 pm2；PaaS 把它藏起來了。/health 失敗，正是壞部署被擋下的方式。
  • TLS 在邊緣終結：瀏覽器 ↔ 平台是 HTTPS（Let's Encrypt，自動），平台 ↔ 你的程序在私有網路內走純 HTTP。你的程式碼保持零 TLS。
  • Secure cookie 旗標只在 production（NODE_ENV === "production"）——localhost 沒有 TLS，Secure cookie 會悄悄永遠不被送回。

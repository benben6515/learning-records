快取急救包

第 10 課濃縮成一張卡：把關每個快取的規則、你為 session 蓋的 cache-aside 骨架、失效法則、誠實取捨表，還有讓一個 Map 變成說謊機的各種坑——依據 cache-aside 模式。把我印出來。

規則零（把關一切）

沒有測量過、重複、而且昂貴的讀取，就沒有快取。先測量（log 那個 query、走一個循環、數次數）。快取證據點名的東西——不是你想像得到的東西。一個你無法說明正當性的快取，是你刻意安裝的說謊機器。

Cache-aside 骨架（永久收藏）

const cache = new Map()                 // key → { value, expires }——行程內記憶體
const TTL = 60_000                      // 你親手選的說謊窗口

async function getAnswer(key) {
  const hit = cache.get(key)
  if (hit && hit.expires > Date.now()) return hit.value       // 中：零 DB query
  const value = await expensiveQuery(key)                     // 沒中：問真相
  cache.set(key, { value, expires: Date.now() + TTL })        // 記住它
  return value
}

快取是一次性的。重啟＝空快取＝無人察覺。資料庫是真相；記憶體是帶有效期的傳聞。

失效法則

await pool.query("DELETE FROM sessions WHERE sid = $1", [sid])
sessionCache.delete(sid)          // 每個突變點都欠這一行
政策新鮮度成本
不快取永遠為真每個讀取都付 DB 的錢
只有 TTL最舊到 TTL 為止零簿記，但突變不會傳播
每個突變點都清除突變時刻為真漏一個突變點 → 快取說謊
TTL＋清除真實世界的預設值production 快取都在做的

值得現在就知道的坑

  • 說謊窗口是商業決策。「被撤銷的 session 也許在 TTL 用完前還能用——除非你動手清。」session 收緊（秒級）、匯率放鬆（分級）、CSS 檔永遠。
  • 快取 key 是租界邊界。每用戶資料的 key 沒帶 user id，就會把陌生人的資料互相端上桌——IDOR 家族藉著一個 Map 轉世。
  • 找齊所有突變點。sessions 表正好一個（logout）。哪天做「登出所有裝置」批次刪 session → 繼承同樣的清除義務。
  • 無界 Map 永遠不縮。每個見過的 key 都留著，直到某個請求發現它過期。真正的快取會驅逐（LRU、大小上限），或把記憶體外包給有上限的獨立行程（Redis）。
  • 圍籬抓得到謊言。先寫合約測試（logout → 401）；加快取；看測試轉紅；加清除；轉綠。紅燈就是快取在自首。
  • HTTP 快取是另一層。瀏覽器與代理用 Cache-Control 標頭快取整個回應——跟你行程內的 Map 無關。你的 API 預設一個都不送，對需要驗證的 API 來說這是對的。
  • 兩個行程無法共享一個 Map。服務擴到 2＋ 個執行個體，各自擁有自己的謊言。那時記憶體搬去 Redis——同一個模式，共享記憶體。

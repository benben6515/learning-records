HTTP 解剖與 curl 速查表

請求／回應模型、狀態碼、標頭，以及把它們現形的 curl 指令——濃縮自 MDN HTTP 與第 01 課。適合列印。

一場交易的全程

每次 HTTP 交換都是：用戶端送出請求（request）（方法＋路徑、標頭、可省略的內文）→ 伺服器送回回應（response）（狀態碼、標頭、可省略的內文）。伺服器就是一個函式：請求進、回應出。

GET /echo HTTP/1.1            ← 請求起始行：METHOD 路徑 版本
host: localhost:3000          ← 標頭：名稱: 值，一行一個
content-type: application/json
                              ← 空行，接著是（可省略的）內文
{"msg":"hi"}
HTTP/1.1 201 Created          ← 回應狀態行：版本 狀態碼 原因
content-type: application/json
                              ← 空行，接著是內文
{"youSent":"hi"}

方法（你真的會用到的動詞）

方法意義有內文？冪等？
GET讀取資源無是
POST建立／提交有否
PUT整個取代資源有是
PATCH部分更新有否*
DELETE刪除資源少用是

*冪等（idempotent）＝同樣的呼叫重複送，伺服器狀態不變。（PATCH 語意因實作而異——MDN：HTTP request methods。）

你會用到的狀態碼

狀態碼讀作典型時機
200 OK資料在這成功的 GET / PUT / PATCH
201 Created新東西建好了成功建立的 POST
204 No Content辦完了，無話可說成功的 DELETE
301 Moved Permanently它搬到別處了永久網址變更
304 Not Modified你的快取還新條件式 GET（ETag）
400 Bad Request你的請求有問題驗證失敗
401 Unauthorized你是誰？缺少／錯誤的憑證
403 Forbidden知道是你，但不行權限不足
404 Not Found沒有這個東西未知路徑／資源
409 Conflict狀態相衝突重複建立、版本過舊
429 Too Many Requests慢一點速率限制
500 Internal Server Error我們弄壞了未處理的例外
502 / 503上游掛了／不可用代理連不到應用

家族：2xx 成功 · 3xx 重導向 · 4xx 用戶端的鍋 · 5xx 伺服器的鍋（MDN：狀態碼）。

你會一直遇到的標頭

標頭方向職責
content-type雙向內文是什麼——application/json、text/html……
content-length雙向內文的位元組數
authorization請求憑證——通常是 Bearer <token>
cache-control回應誰可以快取、快多久
cookie / set-cookie請求／回應伺服器先前設在用戶端的狀態
location回應下一步去哪（伴隨 3xx / 201）

curl 速查表

$ curl http://localhost:3000/                    # GET（預設）
$ curl -i http://localhost:3000/                 # 加上狀態行與標頭
$ curl -X POST -d "name=ben" http://localhost:3000/echo
│            │                                 │
│            └─ 請求內文                       └─ URL
└─ HTTP 方法（GET 是預設，所以 GET 不用旗標）
$ curl -i -X POST \
       -H "content-type: application/json" \
       -d '{"name":"ben"}' \
       http://localhost:3000/echo                # 正統的 JSON 送法
$ curl -s http://localhost:3000/ | jq           # 安靜模式 + 美化輸出
$ curl -o /dev/null -w "%{http_code}\n" URL      # 只要狀態碼

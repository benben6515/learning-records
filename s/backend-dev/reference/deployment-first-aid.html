Deployment First Aid

Lesson 09 in one card: the config rule, the fail-fast guard, the Render settings that shipped your API, the health check, and the gotchas a fresh database will hand you — grounded in the twelve-factor Config principle and the Render Node guide. Print me.

The rule

Same commit everywhere; the environment carries the differences. Port, database URL, secrets enter only through process.env, read at boot. Nothing environment-specific lives in code, in the repo, or in .env files that get committed.

Config starter (copy forever)

// server7.mjs
const PORT = process.env.PORT ?? 3322        // platform assigns; 3322 is local fallback

// utils/db.mjs — fail fast, before any request can 500
if (!process.env.DATABASE_URL) {
  console.error("DATABASE_URL is not set — refusing to start without a database")
  process.exit(1)
}
const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL })
$ node --env-file=.env server7.mjs     // local: Node ≥ 20.6, zero deps

The health check (deep, not shallow)

async function health(_req, res) {
  try {
    await pool.query("SELECT 1")                 // probe the dependency you can't work without
    return json(res, 200, { ok: true })
  } catch {
    return fail(res, 503, "UNHEALTHY", "database unreachable")
  }
}
// routes: { method: "GET", pattern: "/health", handler: health }

"Process alive" ≠ "service works". The check proves the whole chain: process up and database reachable. 503, never 500 — a health check failing is not a bug, it's a status.

Verify the deploy (your own curls)

$ curl -i https://your-app.onrender.com/health          // 200 {"ok":true} — over real HTTPS

Gotchas worth knowing now

  • A fresh database replays the ledger exactly. Any fix applied live to your local DB but never written into a migration file resurfaces in production. Fix the file, redeploy — the repo is the source of truth or nothing is.
  • Free Postgres is a rental: expires 30 days after creation, 14-day grace, then deletion. Re-creating it is free practice: new URL, same migrate, same deploy.
  • Free web services sleep after ~15 min without traffic; first visitor waits ~1 min (cold start). Health checks don't prevent sleep — they prevent lying. Paid instance removes it.
  • Listen on process.env.PORT or the platform's router never finds you. Bind the fallback with ?? so local habits survive.
  • Secrets live in the dashboard, never the repo. DATABASE_URL leaked? Rotate it (one click), update the env var, redeploy — no code change.
  • Crashes get restarted by the platform's supervisor. On a VPS that's your systemd unit or pm2; a PaaS hides it. /health failing is how bad deploys get rejected.
  • TLS terminates at the edge: browser ↔ platform is HTTPS (Let's Encrypt, auto), platform ↔ your process is plain HTTP inside the private net. Your code stays TLS-free.
  • Secure cookie flag only in production (NODE_ENV === "production") — localhost has no TLS, and a Secure cookie would silently never be sent back.

HTTP Anatomy & curl Cheat Sheet

The request/response model, status codes, headers, and the curl commands that show them — compressed from MDN HTTP and Lesson 01. Print me.

The transaction

Every HTTP exchange is: client sends a request (method + path, headers, optional body) → server sends a response (status, headers, optional body). The server is one function: request in, response out.

GET /echo HTTP/1.1            ← request start line: METHOD path version
host: localhost:3000          ← headers: name: value, one per line
content-type: application/json
                              ← blank line, then (optional) body
{"msg":"hi"}
HTTP/1.1 201 Created          ← response status line: version CODE reason
content-type: application/json
                              ← blank line, then body
{"youSent":"hi"}

Methods (the verbs you'll actually use)

MethodMeaningHas body?Idempotent?

*Idempotent = repeating the same call leaves the server in the same state. (PATCH semantics vary — MDN: HTTP request methods.)

curl cheat sheet

$ curl http://localhost:3000/                    # GET (the default)
$ curl -i http://localhost:3000/                 # + status line & headers
$ curl -X POST -d "name=ben" http://localhost:3000/echo
│            │                                 │
│            └─ request body                  └─ the URL
└─ HTTP method (GET is the default, so GET needs no flag)
$ curl -i -X POST \
       -H "content-type: application/json" \
       -d '{"name":"ben"}' \
       http://localhost:3000/echo                # JSON the proper way
$ curl -s http://localhost:3000/ | jq           # quiet + pretty-print
$ curl -o /dev/null -w "%{http_code}\n" URL      # just the status code

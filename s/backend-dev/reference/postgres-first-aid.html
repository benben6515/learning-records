PostgreSQL First Aid

Lesson 06 in one card: the container command, the connection string, the 30-line migration runner, $n params, the error codes worth memorizing, and the psql commands to see everything — compressed from the node-postgres docs and postgresql.org. Print me.

Start / stop / nuke the "other machine"

$ docker run -d --name bd-pg -e POSTGRES_PASSWORD=dev -e POSTGRES_DB=notes -p 5432:5432 postgres:17-alpine
$ docker start bd-pg                  # after a reboot / teardown pause
$ docker exec bd-pg pg_isready -U postgres
$ docker rm -f bd-pg                  # nuke it — migrations rebuild everything
$ export DATABASE_URL="postgres://postgres:dev@localhost:5432/notes"
//        user ─┘└pass┘ └host┘└port┘└db

The migration pattern (any tool, same bones)

migrations/
  0001_init.sql          // numbered, ordered, run once — never edit an applied file
  0002_add_done.sql
  0003_add_priority.sql

// the runner, distilled:
ledger  = CREATE TABLE IF NOT EXISTS schema_migrations (name TEXT PRIMARY KEY, …)
applied = SELECT name FROM schema_migrations
for file of sorted(migrations/*.sql) not in applied:
    BEGIN; run(file); INSERT INTO schema_migrations; COMMIT   // or ROLLBACK

Querying from Node (pg)

import pg from "pg";
const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL });

const rows = (await pool.query("SELECT * FROM notes WHERE id = $1", [7])).rows;
const n    = (await pool.query("DELETE FROM notes WHERE id = $1", [7])).rowCount;
// $1, $2 … numbered params — same anti-injection rule as SQLite's ?
// rows[] = SQLite's .all();  rowCount = .changes();  rows[0] = .get()

See it with psql

$ docker exec -it bd-pg psql -U postgres -d notes
notes=# \d notes                       # table shape: columns, types, constraints
notes=# \dt                            # all tables (incl. schema_migrations)
notes=# SELECT id, title FROM notes;
notes=# \q
// one-shot:
$ docker exec bd-pg psql -U postgres -d notes -c "SELECT * FROM schema_migrations;"

Gotchas worth knowing now

  • Pool ≠ Client. Pool keeps warm connections for a long-lived server; Client is one connection for scripts (our migrate.mjs borrows one via pool.connect() so BEGIN/COMMIT stay on a single connection).
  • Identity ids are unique, not gap-free. Failed inserts still burn sequence values — my test run produced ids 1, 4, 7. Never build logic on contiguity.
  • ECONNREFUSED ::1 before 127.0.0.1 is Node trying IPv6 first. The fix is a running database, not a different host string.
  • Dates are TIMESTAMPTZ — an instant with a timezone, serialized as ISO (2026-09-08T03:30:22.111Z). Store instants, render timezones at the edge.

Password storage (node:crypto, zero deps)

import { randomBytes, scrypt as _scrypt, timingSafeEqual } from "node:crypto";
import { promisify } from "node:util";
const scrypt = promisify(_scrypt);

async function hashPassword(password) {           // register
  const salt = randomBytes(16).toString("hex");
  const hash = (await scrypt(password, salt, 64)).toString("hex");
  return `${salt}:${hash}`;
}
async function verifyPassword(password, stored) { // login
  const [salt, hash] = stored.split(":");
  const test = await scrypt(password, salt, 64);
  return timingSafeEqual(Buffer.from(hash, "hex"), test);
}

Hash ≠ encrypt (no un-anything). Slow on purpose (brute-force economics). Salt per user (rainbow tables die). timingSafeEqual (timing attacks). Async form — sync blocks the loop.

A JWT is signed, not encrypted — echo MIDDLE | base64 -d proves it. Signature = tamper-evidence, not secrecy.

Gotchas worth knowing now

  • Never store, log, or email passwords. The column is password_hash; verify with verifyPassword, full stop.
  • Authorization is a WHERE clause. List: WHERE user_id = $1. Read-one: fetch then compare owner. Most IDOR CVEs are a missing one of those two.
  • DB constraints back you up. UNIQUE email → 23505 → 409. OWASP rule, engine-enforced.
  • Port 3000 might be taken (a Vite dev server took mine mid-verification). EADDRINUSE is not a bug — it's the OS being honest; pick another port.

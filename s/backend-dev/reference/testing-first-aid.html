Testing First Aid

Lesson 08 in one card: the node:test essentials, the AAA shape, the integration-test skeleton you'll reuse forever, red-green rules, and what to test first — compressed from the node:test and node:assert docs plus Fowler's TDD. Print me.

The runner (zero installs)

$ node --test                        // runs every *.test.mjs recursively
$ node --test utils/get-sid.test.mjs  // one file
$ node --test --test-name-pattern="decoy"   // one test by name
// package.json: "scripts": { "test": "node --test" } → npm test

The shape of a test

test("returns the sid when a decoy cookie merely starts with sid", () => {
  const req = { headers: { cookie: "sidebar=hide; sid=the-real-one" } };  // 1 arrange
  const got = getSid(req);                                                // 2 act
  assert.equal(got, "the-real-one");                                      // 3 assert
});

One behavior per test. Name = a sentence that fails readably: ✖ returns the sid when a decoy…. Assertions: assert.equal / notEqual / ok / deepEqual / throws (import from node:assert/strict).

The integration skeleton (copy forever)

import test from "node:test";
import assert from "node:assert/strict";
import { start } from "./server7.mjs";          // server exports start(port), no bare listen

let app, base;
const api = (path, opts = {}) => fetch(base + path, opts);

test("…", async () => {
  app = await start(0);                         // ephemeral port — parallel-safe
  base = `http://localhost:${app.address().port}`;
  const mail = `t${Date.now()}@x.dev`;          // unique data per run — no fixtures
  const res = await api("/auth/login", { … });
  assert.equal(res.status, 200);
  const cookie = res.headers.getSetCookie()[0].split(";")[0];   // "sid=…"
});
test.after(() => app?.close());

Red-green-refactor rules

RuleWhy
Watch every new test fail firsta test that can't fail can't tell you anything (mutation check: re-break, see red, revert)
Red → simplest honest greenno gold-plating while red; the test defines "done"
Refactor only on greenthe suite is your safety net while you move code
Every bug becomes a testyour suite = every way the code has ever been wrong, each with a tripwire
Run the whole suite on every changeseconds; npm test before every commit, CI later

What to test first (priority order)

  1. The contract: every endpoint's success status + shape (201+Location, 204, list scoping).
  2. The error paths: 400 bad JSON, 401 no/bad session, 403 cross-user, 404, 405+Allow, 409 dup email. Bugs live in error paths.
  3. The invariants: PUT idempotency (second PUT → 200), identical 401 bodies (no enumeration), logout revokes instantly.
  4. Pure functions (getSid-style): cheap, fast, name the exact line when broken.

Gotchas worth knowing now

  • Don't bare-listen() at import time — export start(port); tests need start(0) and parallelism.
  • Unique data per run (Date.now() emails) beats elaborate before/after cleanup fixtures at this scale.
  • Unit caught the character, integration caught the hole — you need both zoom levels; don't pick a favorite.
  • Coverage is a weak target — 100% covered code can still be wrong (tests that assert nothing count as covered). Test behaviors, not lines.

Caching First Aid

Lesson 10 in one card: the rule that gates every cache, the cache-aside skeleton you built for sessions, the invalidation law, the honesty trade-offs, and the gotchas that turn a Map into a liar — grounded in the cache-aside pattern. Print me.

Rule zero (gates everything)

No cache without a measured, repeated, expensive read. Measure first (log the query, walk one cycle, count). Cache what the evidence names — not what you can imagine. A cache you can't justify is a lie generator you installed on purpose.

The cache-aside skeleton (copy forever)

const cache = new Map()                 // key → { value, expires } — per-process memory
const TTL = 60_000                      // the lying window you chose

async function getAnswer(key) {
  const hit = cache.get(key)
  if (hit && hit.expires > Date.now()) return hit.value       // hit: zero DB queries
  const value = await expensiveQuery(key)                     // miss: ask the truth
  cache.set(key, { value, expires: Date.now() + TTL })        // remember it
  return value
}

Cache is disposable. Restart = empty cache = nobody notices. The database is truth; memory is a rumor with an expiry date.

Gotchas worth knowing now

  • The stale window is a business decision. "A revoked session may still work for the rest of the TTL — unless you evict." Sessions tight (seconds), currency rates loose (minutes), CSS files forever.
  • Cache keys are tenancy boundaries. Per-user data keyed without the user id serves strangers each other's data — the IDOR family reborn through a Map.
  • Find ALL the mutation points. For sessions: exactly one (logout). A "logout everywhere" feature deletes many sessions → inherits the same eviction duty.
  • An unbounded Map never shrinks. Every key ever seen lingers until a request checks it past expiry. A real cache evicts (LRU, size caps) or outsources memory to a bounded process (Redis).
  • The fence catches the lies. Write the contract test first (logout → 401); add the cache; watch the test go red; add eviction; green. Red is the cache confessing.
  • HTTP caching is a different layer. Browsers and proxies cache whole responses via Cache-Control headers — nothing to do with your in-process Map. Your API sends none by default, which is correct for an authenticated API.
  • Two processes can't share a Map. When your service scales to 2+ instances, each has its own lie. That's when the memory moves to Redis — same pattern, shared memory.

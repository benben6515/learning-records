第 01 課 · 方法

45 分鐘藍圖

你已經能寫出一個可以一路解釋到 node:http 的伺服器——整整八課的份。面試不會考你這個。它會丟給你一個產品名稱，加上 45 分鐘的濃霧，然後評分你在霧裡如何自處。今天：把濃霧變成時刻表的藍圖。

約 30 分鐘 方法 口說

面試官到底在評分什麼

沒有人期待你重現 Instagram 真正的線上架構圖——出題問「設計 Instagram」的面試官自己也畫不出來。他們探的是模糊之下的結構化思考：你是先問還是先畫？你方塊背後的數字經得起算嗎？被逼進單一元件時，你能否深入——還是只是把總覽講得更大聲？System Design Primer 說得很直白：面試官評的是你怎麼解決問題，不是你背得出什麼最終解法。這是好消息：方法可以練。背下來的圖不行——追問永遠找得到背誦的邊界。

核心觀念

面試評的是方法，不是最後那張圖——而方法有四個拍子，各帶時間預算。把時鐘從面試官手上偷過來：大約 5 分鐘需求、5 分鐘估算、15 分鐘高層設計、20 分鐘深潛。這些階段不是官僚流程；每一拍的存在都是為了讓下一拍安全（PDF：ByteByteGo 檔案庫 p.162——System Design Topic Map；p.134——本課程將逐階段走過的 20 個核心概念）。

1 · 需求 — 5′→ 2 · 估算 — 5′→ 3 · 高層設計 — 15′→ 4 · 深潛 — 20′
從第 4 步起，面試官掌舵——他指向哪個方塊，就深入哪個
訊號勝過完整：一張守得住的半成品圖，勝過一張無法解釋的完整圖。
  1. 需求與範圍（requirements & scope，5′）。用自己的話複述題目，然後釘死功能範圍——你要設計的 2–3 個核心功能——和非功能範圍：多少用戶（DAU）、讀寫比、延遲目標、一致性需求。把假設說出口，讓面試官便宜地糾正你：「我假設 1000 萬 DAU、讀多寫少——請糾正我。」
  2. 粗略估算（back-of-envelope estimation，5′）。從 DAU 推出各個數量級：QPS（讀、寫分開算）、每天新增儲存量、快取需要多少記憶體。用 2 的冪、整數、零位數表演——重點是量級正確，不是小數點。完整練習下一課。
  3. 高層設計（high-level design，15′）。畫出方塊：client → DNS/CDN → 負載平衡器（load balancer）→ 應用伺服器 → 資料庫、快取、佇列（queue）按需登場。然後做出區分候選人的那一步：把一個具體請求沿著你自己的圖從頭走到尾——就是你 curl → 路由 → SQL 的走法，只是這次講給陌生人聽。
  4. 深潛與取捨（deep dives & trade-offs，20′）。面試官挑一個方塊說「再深入」——分片？快取失效？熱 key？贏的句型永遠一樣：「這裡我選 X 而不是 Y，因為我在買 ___，代價是 ___。」每個設計選擇都在拿什麼換什麼；把交換說出來，就是這份工作。

面試官評什麼——以及你已經擁有哪些

下面的評分表是 System Design Primer、Alex Xu 的框架、與各家 rubrics 的公約數。右欄最重要：這不是你的第一門技能課——評分表有一半已經在你手上，來自 Backend Fluency。

訊號長什麼樣你從哪裡已經擁有
界定範圍先問再畫；假設說出口L04——寫程式前先釘死行為
估算數量級正確，用算的不是用背的L02——計時實驗、讀懂數字
資料流一個請求沿著圖走完全程L01–L03——curl → handler → response，零魔法
取捨流暢度每個方塊都有具名代價L04–L07——冪等、401 vs 403、session vs token
按需深入鑽進單一元件而不迷路L05–L06——SQLite → Postgres：你換過一次資料層

真正新的只有兩樣：規模詞彙（複製 replication、分片 sharding、快取 caching——本課程第一到三階段）與口說、限時的形式——所以這裡每課都以開口練習收尾，不只是閱讀。

示範一次骨架——短網址服務的四行版

完整走一輪會是第四階段的總整課；這裡壓縮出現一次，證明藍圖裝得下任何題目。看同樣四拍如何撐起一個真答案：

拍子你產出什麼（草圖層級）
需求兩個功能：縮短長網址、快速轉址；帳號／分析當場說出「先不做」。假設每月 1000 萬條新連結、讀多寫少約 100:1。
估算約 4 寫/s、約 400 讀/s——一台還過得去的伺服器今天就撐得住；但要為成長設計，不為這個數字。
高層設計client → LB → 極小的應用層 → 唯一 ID 服務（計數器＋base62）→ key-value store；熱門連結前面放快取。
深潛為什麼不直接 hash 網址（碰撞）· 301 vs 302 的取捨 · 一條連結爆紅時什麼先壞（熱 key → 快取它）。

注意估算故意證明了系統很小——然後設計照樣往下做，因為面試官評的是你對成長的判斷力，不是今天的流量。這一步——「先算出來，再設計著穿越它」——比任何背來的圖都值錢。

實戰練習——紙上排練方法，然後開口

動手做 · 15 分鐘，只用紙筆
  • 翻開檔案庫讀兩頁，畫地形圖式地讀、不做筆記：System Design Topic Map（p.162）與 20 個核心概念（p.134）——你是在跟未來的課程見面，不是在讀書
  • 挑一個你今天用過的 app（X、Spotify、Uber）。寫下：2 個功能需求、2 個非功能需求、1 個說出口的假設。三分鐘。
  • 為「設計一個 pastebin」寫四步驟骨架：四個標題、各一條 bullet。最多十行——紀律就在簡短裡。
  • 手機計時，3 分鐘內把骨架講出來。面試是口說的；這塊肌肉跟寫字那塊是分開的。
  • 把摩擦帶來問 agent（我）：骨架哪裡讓你覺得武斷？哪一步像在拖時間？那份不舒服才是真正的課綱。
